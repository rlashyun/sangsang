# 역할 분담

> 4명의 담당 영역과 협업 규칙. 공통 규칙은 `AGENTS.md`가 원본이며, 이 문서는 **누가 무엇을 책임지는지**만 다룬다.
> 핵심은 두 가지 — **검색과 DB를 분리하고, DB·RPC의 최종 소유권을 데이터 담당에게 모은다.** PRD의 M1(데이터 신뢰성)·M2(탐색 품질)·D6(React 전환)과 맞춘 구조다.
> 기준: [노션 역할분담 페이지](https://app.notion.com/p/3e8ae89171e980afb989ee2c316bdab6) (2026-09-27 확인). 제품 일정·요구사항은 `docs/PRD.md`를 따른다.

소유 영역은 수정 금지 경계가 아니라 최종 책임을 정하는 기준이다.

## 2. 담당별 책임

### 강지현 — 데이터·DB 신뢰성

현재 프로젝트에서 가장 중요한 운영 역할이다.

- 경찰청 두 API 수집
- 카테고리 선별과 멱등 upsert
- 보관기관 `matched/unmatched/ambiguous` 처리
- 별칭과 관서 개편 반영
- DB 인덱스·RPC·마이그레이션
- 보존기간 삭제와 크론 실행
- `ingestion_runs` 모니터링

DB 조회 지연, 대량 삭제, 기관 매칭률 문제의 **1차 담당자이자 DB·RPC 변경의 최종 소유자**다.

### 김성현 — 검색·AI 품질

데이터를 가져오거나 API를 제공하는 역할과 분리한다.

- 퍼지 검색 알고리즘
- 검색어 정규화
- 필드별 가중치와 임계값
- 검색 평가셋 구축
- TOP-3·TOP-5, 거절 성능, nDCG 측정
- 향후 이미지 임베딩 검색

DB 마이그레이션이나 `integrations/supabase.py`는 원칙적으로 소유하지 않는다. 검색에 필요한 DB 변경은 강지현에게 요구사항을 전달하고 함께 작업한다.

### 김택수 — 프론트엔드·UX

React 전환(D6)이 완료된 현재 프론트엔드 소스와 UX를 담당한다.

- `frontend/`의 React 소스와 프론트 테스트 (`web/static/`은 빌드 결과)
- 지도 핀·클러스터·반경 UI
- 습득물 카드와 검색 결과
- 1km·3km·5km 선택 (D4)
- 모바일 반응형
- 로딩·오류·0건 화면
- 디자인 토큰과 컴포넌트

API 응답 형식이 바뀌어야 하는 기능은 권희준과 계약을 먼저 정한 뒤 작업한다(4장).

### 권희준 — 백엔드 API·플랫폼

프론트엔드와 데이터 계층 사이의 계약을 책임진다.

- `/api/institutions`, `/api/found-items`
- 장소·주소 검색 API
- 입력값 검증과 한국어 오류 응답
- Pydantic 응답 스키마
- CDN 캐시와 보안 헤더
- 환경 변수와 Preview·Production 분리
- Vercel 설정, CI, 배포 상태
- 외부 장애·응답시간 모니터링

강지현이 DB 구조를 바꾸더라도 외부 API 응답이 깨지지 않도록 검토한다.

## 3. 협업 규칙

### 3.1 다른 담당 영역을 수정할 때

소유 폴더 밖 수정을 금지하지는 않는다. 하나의 기능이 여러 폴더를 건드리는 경우가 많아 전면 금지는 오히려 개발을 막는다.

> **AI든 사람이든 다른 담당 영역을 수정해야 할 때는 수정할 파일과 이유를 PR 설명에 먼저 밝힌다.**

### 3.2 개인별 장기 브랜치를 만들지 않는다

`강지현-브랜치`처럼 사람 단위 브랜치를 계속 유지하면 결국 크게 충돌한다. 작업마다 짧은 브랜치를 만든다. 이름 규칙은 `AGENTS.md` 10장의 `{type}-{짧은-설명}`을 따른다.

```
fix-db-map-count-query
fix-stable-pagination
feat-radius-selector
test-search-evaluation-set
```

### 3.3 이슈 하나에 최종 책임자(DRI)는 한 명

여러 명이 참여하더라도 최종 책임자는 한 명만 둔다. 예 — 지도 RPC 성능 개선:

| 역할 | 담당 |
| --- | --- |
| 최종 책임 (DRI) | 강지현 |
| API 검토 | 권희준 |
| 매칭 결과 검증 | 김성현 |
| 화면 회귀 확인 | 김택수 |

## 4. API 계약을 먼저 확정한다

프론트와 백엔드를 동시에 수정하기 전에 다음을 먼저 정한다. 계약이 정해진 뒤 김택수와 권희준이 각각 구현하면 충돌이 크게 줄어든다.

- 요청 파라미터
- 응답 필드와 타입
- 오류 코드와 메시지 (400 / 502 / 503 / 500 구분 — `AGENTS.md` 4장)
- 빈 결과 형식
- 페이징 방식
