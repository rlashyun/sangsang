## 2. 작업별 메모

### 1. 전체 물품으로 확대 · 데이터베이스 전반 수정 — 권희준

- 기존 6개 서비스 카테고리 제한을 없애고 전체 물품을 다룬다.
- 수집 단계의 분류 제한과 DB의 카테고리·조회 구조 등 영향을 받는 부분을 확인하고 함께 수정한다. 구체적인 스키마·백필 방식은 구현 전에 정한다.
- 검색·임베딩·화면에 전달되는 분류가 바뀌면 김성현(2번), 강지현(4번)과 계약을 맞춘다.
- PRD 2.2·3.1·4.5의 기존 카테고리 제한과 `AGENTS.md`의 관련 규칙·용어를 구현과 함께 갱신한다. 현재 수집이 이미 전체 물품을 지원한다고 표시하지 않는다.
- DB 변경은 기존 마이그레이션을 고치는 대신 새 마이그레이션으로 남기고, 앱과 DB의 적용 순서 및 복구 방법을 PR에 적는다.
- **2026-11-20 진행:** 수집 코드·마이그레이션 `20261120090000_all_item_categories.sql`·PRD·AGENTS 반영(브랜치 `feat-all-item-categories`). 분류는 상위분류 21개 + 기타물품 대체. 검색 종류 판정(`synonyms.KIND_NAMES` 6종)과 DB `search_kind_mask`는 바꾸지 않았다 — 새 분류 물품은 종류 단어가 없는 검색어로 찾힌다(2번 김성현 확인 필요). 이용안내 물품 목록·대체 그림 규칙만 최소 수정했다(4번 강지현 확인 필요). 운영 DB 적용·과거 6개월 백필은 병합 후 진행한다.

### 2. 검색 시스템 완성 · 멀티모달 · 하이브리드 · Agent 결합 — 김성현

- 텍스트와 이미지를 활용하는 멀티모달 검색을 추가하고, 하이브리드 검색과 Agent를 결합한다.
- 키워드·의미 검색의 결합 방식, 이미지 처리 경로, Agent가 호출할 검색 도구와 입력·출력을 정해 PRD 4.2·4.5에 반영한다. 특정 모델이나 결합 알고리즘은 이번 역할 배정에서 확정하지 않는다.
- 권희준(1번)의 전체 물품 확장과 DB·조회 계약을 맞추고, 김택수(5번)와 검색 담당 Agent와 추가 기능의 경계를 맞춘다.
- 원문 보존, 위치 기반 검색 범위, 검색 응답 무캐시, 유사도 수치 비노출 등 기존 가드레일을 유지한다. 변경이 필요하면 PRD에 명시한다.
- 검색 품질·지연·비용을 검증하고 측정 조건과 결과를 `docs/measurements.md`에 남긴다.

### 3. 이미지 로딩 시간 초과 해결 — 김택수

- 목록·상세 이미지가 어느 경로에서 시간 초과되는지 재현하고 원인을 확인한다.
- 로딩 중·사진 없음·로딩 실패 상태를 구분하고, 실패 때문에 목록이나 상세 이용이 막히지 않게 한다.
- 수정 전후의 확인 결과를 남긴다. 시간을 측정했다면 조건과 함께 `docs/measurements.md`에 기록한다.
- 이미지 검색 처리(2번)와 화면 개편(4번)이 같은 이미지 컴포넌트를 바꾸면 착수 전에 순서를 맞춘다.

### 4. 디자인 전반 개선 · 디자이너 섭외 검토 — 강지현

- 화면 전반에서 AI가 만든 듯한 인상을 줄이고 서비스에 맞는 시각적 일관성을 갖추도록 다듬는다.
- **디자이너 섭외는 검토 중이다.** 섭외 여부, 협업 방식, 구체적인 디자인 방향은 아직 확정하지 않았다.
- 작업 전 PRD → `docs/ui-patterns.md` → `docs/design-system.md` → `docs/frontend-guidelines.md` 순서로 확인한다.
- 이미지 상태(3번)와 지도 이동(6번)을 함께 고려하고, 모바일·키보드 접근성·loading·empty·error·disabled 상태를 유지한다.

### 5. 검색 외 Agent 활용 방안 — 김택수

- 검색 로직 외에 Agent가 도울 수 있는 일을 검토한다. **당근 탐색은 후보 예시이며 구현 확정 사항은 아니다.**
- 후보별 사용자 이점과 데이터 접근 가능성·제약을 확인해 적용 여부와 이번 개발 범위를 정리한다.
- 김성현(2번)과 Agent의 역할·도구 경계를 맞추고, 확정된 동작은 PRD에 반영한다.

### 6. 지도 이동 애니메이션 — 권희준

- 지도 중심 이동이 자연스럽게 이어지도록 애니메이션을 적용한다.
- 적용할 이동 상황과 동작은 강지현(4번)과 맞춰 정한다. 기존 장소 선택·반경·기관 선택 동작을 유지한다.
- 움직임 감소 설정을 고려하고, 데스크톱과 모바일에서 이동 후 선택 상태가 일치하는지 확인한다.

### 7. 습득물 개인정보 마스킹 — 권희준

- 경찰청 원문의 `item_name`에 카드번호·이름·전화번호·주민번호 형식이 그대로 들어 있어(PRD 3.3, Q5; 수치는 `docs/measurements.md`), **저장 원문은 그대로 두고 밖으로 나가는 사본만 가린다.** 가리는 곳은 `/api/found-items` 응답, 대화 검색의 브라우저·LLM 전달값, 알림 메일, 해외 임베딩 API 입력, 정규화 칸 `normalized_search_text`다. 규칙은 `privacy/masking.py`, 기존 정규화 칸 재마스킹은 `privacy/remask.py`다.
- 번호 형태(카드·주민·전화) 검색어는 지도 검색·대화 검색·알림 예약에서 거절한다. 원문 보존(2장 규칙 3)은 바꾸지 않는다.
- **2026-11-20 진행:** 마스킹 도입(PR #69)과 카드번호 앞 4·뒤 4자리 노출 변경(PR #70)은 병합했다. 괄호 속 이름 규칙 조정(2자 괄호 단어는 가리지 않고 3자·성씨 시작만 가림)은 브랜치 `fix-bracket-name-rule`에서 진행 중이다.
- **남은 일:** 운영 DB 정규화 칸 재마스킹(실행은 사용자 승인 후) → 마스킹 전 원문으로 만든 새 물품 임베딩 재생성 → BM25 검색 문서(`search_text`)·고위험 분류 사진 비노출·처리방침 페이지(`docs/backlog.md` 8장). 이 후속 작업은 이번 스프린트 안에 끝낸다고 확정하지 않았다.
- 검색 문서(BM25)와 임베딩 입력은 김성현(2번), 고위험 분류 사진 비노출은 김택수(3번)·강지현(4번)과 범위를 맞춘다. 심사평가표 책임·윤리 항목이 마스킹 조치 구현을 본다(`docs/evaluation/`).

## 3. 선행 관계와 공동 일정

- **1 ↔ 2:** 전체 물품 확장에 따른 DB·카테고리·검색 입력과 출력 계약을 먼저 맞춘다.
- **1 → 7:** 전체 물품 확장으로 증명서·서류·유가증권·현금 분류가 들어오므로, 7번의 임베딩 재생성과 재마스킹을 끝낸 뒤 남은 경찰 백필·임베딩을 진행한다.
- **2 ↔ 5:** 검색 Agent 결합과 검색 외 활용 방안을 나눠 맡되, 도구와 사용자 흐름이 겹치지 않게 범위를 맞춘다.
- **3 ↔ 4, 4 ↔ 6:** 이미지 컴포넌트·지도·스타일 등 같은 파일을 바꿀 수 있으므로 수정 범위와 병합 순서를 먼저 합의한다.
- **2026-11-21(토): 개발 완료.** 각 담당은 결과를 GitHub에 push하고 PR로 공유한다.
- **2026-11-22(일): 발표자료 제출.** 개발 결과·화면·데모·검증 내용을 바탕으로 자료를 준비한다. 작성·취합·제출 담당은 별도 지정한다.

## 4. 협업 규칙

- 작업마다 최종 책임자(DRI)는 그 작업의 담당 한 명이다.
- 같은 파일을 여러 명이 고칠 때는 착수 전에 순서와 범위를 합의하고, PR에 고친 파일과 이유를 적는다.
- 프런트와 백엔드를 함께 바꾸기 전에는 요청 파라미터, 응답 필드와 타입, 오류 코드와 메시지, 빈 결과 형식, 페이징 방식을 먼저 합의한다.
- 브랜치는 기능·이슈 단위로 만들고 GitHub에 push한 뒤 PR로 공유한다. `main`에 직접 커밋하지 않고, 병합한 브랜치는 정리한다(`AGENTS.md` 10장).
- 이전 스프린트의 미완료 작업은 완료로 간주하지 않는다. 계속 진행할 항목은 `docs/backlog.md`와 기존 PR에서 확인한다. 운영자용 크론 실패 이메일 알림(PRD Q6)의 담당 권희준은 유지한다.
