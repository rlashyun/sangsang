# RETRIEVER 디자인 시스템

> 2026-11-08 사용자 결정에 따른 개편 기준. 현재 CSS 구현 완료를 뜻하지 않는다. 제품 동작은 PRD → ui-patterns.md, 구현은 frontend-guidelines.md 순서로 따른다.

## 1. 시각 방향

DS-01 브랜드 방향은 밝고 부드러운 iOS 나의 찾기 인상으로 확정했다. 영문 `RETRIEVER`, 흰색 표면, 맑은 파란색, 차분한 회색 글씨, 둥근 개별 카드와 은은한 그림자를 사용한다. 과도한 검정 굵은 글씨, 쨍한 파랑, 회색빛 파랑, 강한 테두리로 화면을 나누는 구성을 피한다.

상단 로고 오른쪽에 물건 찾기/새 물건 알림, 오른쪽 끝에 이용안내를 둔다. 새 물건 알림 앞에는 이모지/문자 아이콘을 넣지 않는다. 메뉴를 화면 중앙으로 옮기지 않는다.

## 2. 토큰과 색상

기존 의미 기반 CSS 변수와 `lib/theme.ts`의 지도 토큰 연동을 유지한다. 아래는 새 디자인의 목표 값이며 실제 styles.css의 현재 값이 아니다. 색상·간격·모서리·글씨 크기를 토큰화해 적용하고 컴포넌트마다 값을 중복하지 않는다.

| 역할 | 목표 기준 |
| --- | --- |
| 주요 행동/선택 | 맑은 중간 파랑, 약 #4488EB |
| 제목/주요 글씨 | 부드러운 슬레이트 회색, 약 #5B687A |
| 설명/메타데이터 | 주요 글씨보다 한 톤 밝은 회색 |
| 표면 | 흰색, 보조 영역은 매우 옅은 회청색 |
| 테두리/그림자 | 얇고 옅게, 그룹 구분은 우선 여백 사용 |
| 지도 기관 구분 | 연계기관 파랑, 경찰관서 노랑. 텍스트/모양도 함께 제공 |
| 오류/주의 | 붉은색/주의색과 이해 가능한 문구 |

파랑은 행동·선택·유사도 배지에 제한적으로 사용한다. 색만으로 상태를 전달하지 않는다. 글씨를 부드럽게 표현하되 배경과 구분되지 않을 만큼 옅게 만들지 않는다. 명암비는 실제 적용 색상으로 확인한다.

기존 Warm/Cocoa/Modern 테마 선택기는 과거 비교용이다. 개편에서는 승인한 파란 기본 테마를 기준으로 지도와 일반 UI를 맞추고, 과거 테마가 새 기본값을 덮어쓰지 않게 정리한다.

## 3. 글씨와 버튼

DS-02: 한국어는 부드러운 둥근 인상의 산세리프를 사용한다. 실제 웹폰트의 제공 방식/라이선스와 폴백은 구현 시 확인한다. 시스템 폰트 폴백은 유지한다.

- 큰 제목은 담백한 중간 두께로, 카드 제목은 약 12~14px, 보조 분류/등록일 등은 약 10~12px를 기준으로 한다. 기존 “무조건 12px 이상” 규칙은 이번 카드 디자인에 맞게 조정한다.
- 제목 → 분류/본문 → 메타데이터의 차이를 크기뿐 아니라 여백·두께·색으로 표현한다. 실제 선택한 크기가 읽기 어려우면 카드 수를 줄이거나 배치를 바꾼다.
- 줄 간격은 여유 있게 유지한다. 긴 이름/주소는 영역 안에서 줄바꿈한다. 말줄임한 원문 전체는 상세에서 제공한다.
- 페이지 버튼의 보이는 크기는 약 28~32px로 작게 유지한다. 실제 클릭 영역은 인접 버튼과 겹치지 않게 확보한다. 모바일 기존 터치 사용성도 보존한다.
- 입력·버튼에 label/접근 가능한 이름과 focus-visible을 유지한다. 포커스를 없애지 않는다.

## 4. 검색 패널과 카드

- 전체 화면 지도 위 왼쪽에 둥근 검색 패널을 띄운다. 왼쪽 바깥 여백은 작게, 상하 바깥 여백은 균형 있게 둔다.
- 장소/물품은 각각 분리된 둥근 메시지 카드로 표현한다. 말풍선 꼬리는 넣지 않는다.
- 개별 카드 크기 축소 기준: 장소 높이 약 104px, 물품 약 110px, 카드 간격 약 8px, 세로 패딩 약 9px, 사진 약 52×58px 안의 고정 영역. 이는 디자인 기준값이며 원문 길이/화면 높이에 맞게 조절한다.
- 글씨를 더 작게 만드는 방식으로만 공간을 해결하지 않는다. 사진·패딩과 카드 수를 함께 조정한다.
- 한 페이지는 충분한 높이에서 약 5개까지, 높이가 부족하면 줄인다. 카드 목록/페이지 이동/검색 후 하단 행동 영역을 분리한다. 카드나 텍스트가 페이지 번호를 덮지 않아야 한다.
- 장소 태그는 작은 옅은 배경 캡슐, `#` 없음. 물품 분류는 기존 카드의 작은 경로 텍스트를 유지하고 검색 후 유사도 배지만 추가한다.
- 유사도 배지는 오른쪽 위에 작게 두되 원문 제목·분류를 밀거나 겹치지 않게 한다. 임시값은 예시임을 알린다.

## 5. 지도와 배경 흐림

반경은 강한 테두리 원 대신 은은한 파란 면을 사용하고 가장자리를 투명하게 옅어지게 한다. 실제 필터 거리를 바꾸지 않고 현재 반경을 텍스트로 표시한다. 카카오 기본 타일의 도로·공원 색을 임의로 변경할 수 있다고 가정하지 않는다. 지원하는 SDK 오버레이 방식으로 구현하고 지도 이동/확대에도 정합성을 유지한다.

상세·수령·알림 창에서는 기존 지도/검색 화면을 남기고 흐리게 처리한다. 흰색 창은 불투명하고 글씨는 또렷하게 유지한다. 배경 blur와 은은한 그림자를 사용하되 창 안의 정보까지 흐리게 하지 않는다.

## 6. 상세·수령·알림 창

상세는 노션식 안내 페이지 구조다. 사진/주요 속성을 위에, 원문 설명과 기관 위치를 본문에 둔다. 수령 안내는 연락→준비→방문 확인의 단계와 “확인했어요” 버튼을 사용한다.

알림 창은 검색 패널보다 넓은 가로 구성으로 약 980px 전후를 기준으로 한다. 세로도 여유 있게 두되 화면 상하에 배경이 보이게 한다. 왼쪽 조건 요약/오른쪽 이메일을 배치한다. 글씨와 입력창을 확대해 채우기보다 여백을 늘린다. 작은 창에서는 가용 크기에 맞추고 잘림을 방지한다.

## 7. 사진·대체 이미지

목록과 상세에서 사진이 있으면 원본 전체를 고정 영역 안에 표시한다. 목록은 지연 로딩한다. 기본 그림/빈 URL/실패는 카테고리별 대체 이미지로 바꾸고, 실제 사진처럼 오인시키지 않는다. 기존 categoryIcon을 기반으로 연결하며 최종 대체 에셋은 별도 선정한다. 원문과 출처 데이터는 보존한다.

DS-03: 첫 화면은 작은 위치 안내 그래픽을 사용한다. 빈 결과는 짧은 설명과 다음 행동을 우선하고 추가 장식 일러스트 제작은 필수로 두지 않는다.

## 8. 상태·반응형·검수

기본/hover/focus/active/disabled/loading/error/selected를 제공한다. prefers-reduced-motion을 존중한다. 이번 개편은 데스크톱 우선이며 현재 모바일 세로 배치·상세 하단 시트를 유지한다. 특정 시안 크기에만 맞춰 가로 넘침이나 버튼 잘림을 만들지 않는다.

검수는 긴 원문, 사진 실패, 작은 창 높이, 페이지와 카드 분리, 임시 유사도 안내, 배경 흐림/포커스, 정상·빈 결과·오류를 확인한다. 카드 크기와 글씨가 충돌하면 가독성과 하단 행동 공간을 함께 보존한다.
