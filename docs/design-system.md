# RETRIEVER 디자인 시스템

> 2026-11-08 사용자 결정에 따른 개편 기준. 현재 CSS 구현 완료를 뜻하지 않는다. 제품 동작은 PRD → ui-patterns.md, 구현은 frontend-guidelines.md 순서로 따른다.

## 1. 시각 방향

DS-01 브랜드 방향은 밝고 부드러운 iOS 나의 찾기 인상으로 확정했다. 영문 `RETRIEVER`, 흰색 표면, 맑은 파란색, 차분한 회색 글씨, 둥근 개별 카드와 은은한 그림자를 사용한다. 과도한 검정 굵은 글씨, 쨍한 파랑, 회색빛 파랑, 강한 테두리로 화면을 나누는 구성을 피한다.

상단 로고 오른쪽에 물건 찾기/새 물건 알림, 오른쪽 끝에 이용안내를 둔다. 새 물건 알림 앞에는 이모지/문자 아이콘을 넣지 않는다. 메뉴를 화면 중앙으로 옮기지 않는다.

## 2. 토큰과 색상

기존 의미 기반 CSS 변수와 `lib/theme.ts`의 지도 토큰 연동을 유지한다. 아래는 새 디자인의 목표 값이며 실제 styles.css의 현재 값이 아니다. 색상·간격·모서리·글씨 크기를 토큰화해 적용하고 컴포넌트마다 값을 중복하지 않는다.

| 역할 | 목표 기준 |
| --- | --- |
| 주요 행동/선택 | 맑은 중간 파랑, 약 #4488EB |
| 제목/주요 글씨 | 부드러운 슬레이트 회색, 약 #5B687A |
| 설명/메타데이터 | 주요 글씨보다 한 톤 밝은 회색 |
| 표면 | 흰색, 보조 영역은 매우 옅은 회청색 |
| 테두리/그림자 | 얇고 옅게, 그룹 구분은 우선 여백 사용 |
| 지도 기관 구분 | 연계기관 파랑, 경찰관서 노랑. 텍스트/모양도 함께 제공 |
| 오류/주의 | 붉은색/주의색과 이해 가능한 문구 |

파랑은 행동·선택 상태에 제한적으로 사용한다. 색만으로 상태를 전달하지 않는다. 글씨를 부드럽게 표현하되 배경과 구분되지 않을 만큼 옅게 만들지 않는다. 명암비는 실제 적용 색상으로 확인한다.

기존 Warm/Cocoa/Modern 테마 선택기는 과거 비교용이다. 개편에서는 승인한 파란 기본 테마를 기준으로 지도와 일반 UI를 맞추고, 과거 테마가 새 기본값을 덮어쓰지 않게 정리한다.

## 3. 글씨와 버튼

DS-02: 한국어는 부드러운 둥근 인상의 산세리프를 사용한다. 실제 웹폰트의 제공 방식/라이선스와 폴백은 구현 시 확인한다. 시스템 폰트 폴백은 유지한다.

- 큰 제목은 담백한 중간 두께로, 카드 제목은 약 12~14px, 보조 분류/등록일 등은 약 10~12px를 기준으로 한다. 기존 “무조건 12px 이상” 규칙은 이번 카드 디자인에 맞게 조정한다.
- 제목 → 분류/본문 → 메타데이터의 차이를 크기뿐 아니라 여백·두께·색으로 표현한다. 실제 선택한 크기가 읽기 어려우면 카드 수를 줄이거나 배치를 바꾼다.
- 줄 간격은 여유 있게 유지한다. 긴 이름/주소는 영역 안에서 줄바꿈한다. 말줄임한 원문 전체는 상세에서 제공한다.
- 페이지 버튼의 보이는 크기는 약 28~32px로 작게 유지한다. 실제 클릭 영역은 인접 버튼과 겹치지 않게 확보한다. 모바일 기존 터치 사용성도 보존한다.
- 입력·버튼에 label/접근 가능한 이름과 focus-visible을 유지한다. 포커스를 없애지 않는다.

## 4. 검색 패널과 카드

장소 확정 후 상단 구조(2026-11-08 적용): 작은 “‹ 장소 다시 찾기” 텍스트 버튼 → 장소 제목 한 번(24px/600) → 주소 → 현재 반경 순서다. 영어 섹션 라벨과 중복 장소 제목은 사용하지 않는다. 물품 검색창은 옅은 배경의 둥근 입력창과 원형 파란 검색 버튼으로 구성한다. 상단 반경 버튼은 없애고 제출 검색어가 있을 때만 하단 다음 반경 확장 동작을 제공한다.

- 전체 화면 지도 위 왼쪽에 둥근 검색 패널을 띄운다. 왼쪽 바깥 여백은 작게, 상하 바깥 여백은 균형 있게 둔다.
- 장소/물품은 각각 분리된 둥근 메시지 카드로 표현한다. 말풍선 꼬리는 넣지 않는다.
- 개별 카드 크기 축소 기준: 장소 높이 약 104px, 물품 약 110px, 카드 간격 약 8px, 세로 패딩 약 9px, 사진 약 52×58px 안의 고정 영역. 이는 디자인 기준값이며 원문 길이/화면 높이에 맞게 조절한다.
- 글씨를 더 작게 만드는 방식으로만 공간을 해결하지 않는다. 사진·패딩과 카드 수를 함께 조정한다.
- 장소는 페이지당 4곳 고정, 카드 높이 동일, 긴 제목·주소는 한 줄 말줄임을 적용한다. 물품은 페이지당 4개로 고정하고 마지막 페이지만 남은 개수를 표시한다. 카드 목록/페이지 이동/검색 후 하단 행동 영역을 분리한다. 카드나 텍스트가 페이지 번호를 덮지 않아야 한다.
- 장소 카드 적용(2026-11-08): 개별 흰색 둥근 카드에 이름 17px/700, 주소 13px, 분류 태그 12px을 사용한다. 초기 장소 카드의 전화번호는 생략하고, 분류는 주소 아래에 왼쪽 정렬한 옅은 배경 태그로 표현한다. 장소 카드 목록은 같은 높이의 4행을 사용하고 카드 간격은 8px이다. 긴 원문은 말줄임으로 높이를 유지하며, 미리보기 확인 버튼은 항상 확보한 오른쪽 공간에서만 나타나 선택 전후 카드 크기와 글씨 배치를 유지한다. 개발 화면 오른쪽 아래의 전체 화면 비교로 오늘 UI 수정 전 버전(8f701b0)과 현재 수정안을 비교한다. 기존 화면은 별도 문서로 격리하고 각 화면의 검색 상태를 따로 유지한다. 부분별 지도/카드 비교 버튼은 전체 화면 전환으로 통합했다. 장소 번호 페이지는 적용됐으며 물품 번호 페이지도 적용됐으며 4개씩 고정한다.
- 장소 태그는 작은 옅은 배경 캡슐, `#` 없음. 물품 분류는 기존 카드의 작은 경로 텍스트를 유지한다. 검색 후에도 카드 구조를 바꾸지 않는다.
- 유사도 숫자·%·임시 배지를 카드/상세에 표시하지 않는다. 결과 제목 옆에 “유사도 높은 순” 정도의 정렬 안내만 제공한다.

## 5. 지도와 배경 흐림

검색 반경은 1km, 1.5km, 2km로 표시한다. 결과 하단의 ‘돌아가기’와 ‘넓혀보기’를 나란히 둔다. 색상 옆에는 이전 반경 안의 보관기관 물품에만 ‘1km 이내’ 또는 ‘1.5km 이내’를 표시한다. 반경 변경은 지도와 물품 목록에 함께 반영한다.

2026-11-08 비교 중: 첫 화면의 전국 기관 분포는 유지한다. 오른쪽 아래 전체 화면 비교로 오늘 UI 수정 전 지도/검색 화면과 현재 수정안을 비교한다. 수정안은 클러스터 원을 42px로 통일하고, 파란 배경(불투명도 0.4)과 작은 숫자를 쓴다. 개별 기관은 작은 파란/노란 핀으로 구분하며, 상시 물품 수 배지 대신 선택 시 기관 정보에서 물품 수를 확인한다. 선택 기관에는 강조 링을 표시한다. 핀은 클러스터보다 진한 부드러운 파랑(#72A0E1)/노랑(#D9B653)을 사용하고 상단 기관 수 범례와 색상 토큰을 공유한다. 얇은 흰 테두리와 가벼운 그림자를 사용한다. 핀 이미지 영역은 28×36px이며 내부 표식은 차분한 슬레이트색으로 구분한다. 배경의 흰 Tileset 오버레이는 탁함과 확대·축소 시 색 변화 문제로 제거했다. 일반 지도 타일 이미지에만 CSS 채도(0.75)를 적용해 명암과 선명도를 유지한다. 핀·정보창·카카오 로고에는 필터를 적용하지 않는다. 실제 SDK 타일은 mts.kakaocdn.net/api/v1/tile/ 경로임을 확인해 적용 대상에 추가했다. 검색/확대 후의 타일 호스트 변경에도 적용하도록 /api/v1/tile/ 경로와 이전 지도 경로를 함께 대상으로 삼는다. SDK 타일 URL 구조가 바뀌면 CSS 선택자를 재확인한다. 장소 후보 핀은 작은 파란 핀으로 통일하고, 미리보기/확정 장소는 기관 핀보다 큰 흰색 핀으로 강조한다. 이 처리는 도로/공원별 개별 색상을 바꾸는 기능은 아니다. 비교 버튼과 수정안의 최종 채택 여부는 사용자 검토 후 정리한다. 반경·조회 대상·검색 로직은 이번 비교에서 바꾸지 않는다.

반경 표시 적용(2026-11-08): 테두리를 없애고 중심에서 바깥으로 투명해지는 파란 radial-gradient 면을 사용한다. 중심/중간/외곽 농도는 36%/29%/16%로 두고 반경 끝에서 투명해지도록 한다. SDK AbstractOverlay의 지도 투영으로 반경의 미터 크기를 픽셀에 대응하고 줌·지도 이동 시 다시 그린다. 중심점이 화면 밖으로 나가도 걸쳐 있는 영역은 유지하며 장소/반경 변경·해제·화면 제거 시 기존 오버레이를 정리한다. pointer-events를 끄고 반경 면은 overlayLayer 맨 앞(z-index -1)에 두어 마커·클러스터 아래에 유지한다. 위치/기관 정보창은 z-index 30으로 올려 파란 면에 덮이지 않게 하며 지도·핀 조작을 방해하지 않는다. 실제 필터 거리를 바꾸지 않고 현재 반경을 텍스트로 표시한다. 지도 핀 위의 흰색 위치 안내 박스는 최대 300px 폭 안에서 긴 장소명과 주소를 자연스럽게 줄바꿈하고 높이가 내용에 맞게 늘어나도록 한다. 이 박스에는 말줄임을 적용하지 않으며 제목/주소를 별도 블록과 줄 간격으로 구분한다. 검색 결과의 고정 높이 카드와는 별개다. 카카오 기본 타일의 도로·공원 색을 임의로 변경할 수 있다고 가정하지 않는다. 지원하는 SDK 오버레이 방식으로 구현하고 지도 이동/확대에도 정합성을 유지한다.

상세·수령·알림 창에서는 기존 지도/검색 화면을 남기고 흐리게 처리한다. 흰색 창은 불투명하고 글씨는 또렷하게 유지한다. 배경 blur와 은은한 그림자를 사용하되 창 안의 정보까지 흐리게 하지 않는다.

기관 핀은 34×44px 이미지 영역과 흰 테두리를 공유한다. 연계기관은 진한 파랑(#2459D3)과 흰 중심점, 경찰청은 진한 황금색(#AF720E)과 흰 방패를 사용한다. 기관 범례는 각 핀의 색과 맞춘다. 검색 후보는 옅은 파랑과 번호, 미리보기/확정 장소는 흰 핀으로 구분한다.

## 6. 상세·수령·알림 창

상세는 노션식 안내 페이지 구조다. 사진/주요 속성을 위에, 원문 설명과 기관 위치를 본문에 둔다. 수령 안내는 연락→준비→방문 확인의 단계와 “확인했어요” 버튼을 사용한다.

2026-11-08 상세 창 배치: 데스크톱은 최대 약 960px의 넓은 창에서 왼쪽 큰 사진·출처, 오른쪽 물품명·기본 속성·원문 설명·보관기관을 나란히 배치해 보통 길이의 내용을 스크롤 없이 확인하도록 한다. 상세 사진 영역은 데스크톱 높이 340px(모바일 240px)로 고정하고 이미지는 영역 안에 절대 배치해 object-fit: contain으로 원본 비율을 유지한다. 세로/가로 사진 모두 이 영역 밖으로 흐르지 않게 하고 물품명·기본 정보는 데스크톱에서 사진 오른쪽에 모으고 모바일에서는 사진 아래에 둔다. 사진 없음/실패/로딩 상태도 같은 높이를 유지한다. 매우 긴 원문이나 작은 화면에서는 내용을 생략하지 않고 기존 키보드 스크롤과 고정된 닫기 버튼을 유지한다. 모바일은 기존 세로 하단 시트를 유지한다.

알림 창은 검색 패널보다 넓은 가로 구성으로 약 980px 전후를 기준으로 한다. 세로도 여유 있게 두되 화면 상하에 배경이 보이게 한다. 왼쪽 조건 요약/오른쪽 이메일을 배치한다. 글씨와 입력창을 확대해 채우기보다 여백을 늘린다. 작은 창에서는 가용 크기에 맞추고 잘림을 방지한다.

## 7. 사진·대체 이미지

목록과 상세에서 사진이 있으면 원본 전체를 고정 영역 안에 표시한다. 목록은 지연 로딩한다. 기본 그림/빈 URL/실패는 카테고리별 대체 이미지로 바꾸고, 실제 사진처럼 오인시키지 않는다. 기존 categoryIcon을 기반으로 연결하며 최종 대체 에셋은 별도 선정한다. 원문과 출처 데이터는 보존한다.

DS-03: 첫 화면은 작은 위치 안내 그래픽을 사용한다. 빈 결과는 짧은 설명과 다음 행동을 우선하고 추가 장식 일러스트 제작은 필수로 두지 않는다.

## 8. 상태·반응형·검수

기본/hover/focus/active/disabled/loading/error/selected를 제공한다. prefers-reduced-motion을 존중한다. 이번 개편은 데스크톱 우선이며 현재 모바일 세로 배치·상세 하단 시트를 유지한다. 특정 시안 크기에만 맞춰 가로 넘침이나 버튼 잘림을 만들지 않는다.

검수는 긴 원문, 사진 실패, 작은 창 높이, 페이지와 카드 분리, 유사도 수치 미노출과 정렬 순서, 배경 흐림/포커스, 정상·빈 결과·오류를 확인한다. 카드 크기와 글씨가 충돌하면 가독성과 하단 행동 공간을 함께 보존한다.
