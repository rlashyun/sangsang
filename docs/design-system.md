# 리트리버 디자인 시스템

> 상태: 초안
>
> 이 문서는 리트리버 화면의 시각 언어와 디자인 토큰 기준을 정의한다. 제품 동작과 화면 흐름은 `docs/ui-patterns.md`, React 구현 방식은 `docs/frontend-guidelines.md`를 따른다.

## 1. 목표

리트리버는 분실 직후 불안한 사용자가 빠르게 탐색하는 서비스다. 화면은 다음 원칙을 우선한다.

1. 현재 탐색 위치와 범위를 가장 분명하게 보여준다.
2. 지도와 결과 목록의 관계를 쉽게 이해하게 한다.
3. 장식보다 검색, 선택, 상태 메시지의 가독성을 우선한다.
4. 모바일과 데스크톱에서 같은 정보와 기능을 제공한다.
5. 기존 화면을 한 번에 재설계하지 않고, 수정하는 영역부터 토큰으로 정리한다.

## 2. 현재 시각 방향

`frontend/src/styles.css`의 현재 화면을 기준으로 한다.

- 기본 분위기: 차분하고 신뢰감 있는 밝은 화면
- 주요 색: 녹색 계열
- 보조 구분: 연계기관은 녹색, 경찰관서는 노란색
- 위험·오류: 붉은색
- 정보 구조: 전체 화면 지도 위에 검색·결과 패널을 띄우는 구성
- 모서리: 검색 패널과 입력창·버튼·카드에만 제한적으로 둥근 모서리 사용

> [결정 필요: DS-01] 브랜드의 최종 시각 분위기
>
> - 현재 구현: 차분한 녹색, 둥근 패널, 비교적 부드러운 인상
> - 권장안: MVP 동안 현재 방향을 유지하고 사용자 흐름이 안정된 뒤 브랜드 작업을 진행한다.
> - 결정 영향: 로고, 대표 색, 타이포그래피, 아이콘과 빈 상태 일러스트의 방향이 달라진다.

## 3. 디자인 토큰

현재 화면에 사용 중인 색상은 `frontend/src/styles.css`의 `:root`에 의미 기반 CSS 변수로 구현되어 있다. 새 UI를 만들거나 기존 CSS를 수정할 때 같은 의미의 값을 컴포넌트마다 새로 만들지 않고 해당 토큰을 사용한다.

토큰은 다음 역할별로 나뉜다.

- 기본 표면과 텍스트: `--color-bg-*`, `--color-text-*`
- 브랜드와 행동: `--color-action-*`, `--color-brand-*`, `--color-focus*`
- 상태: `--color-error`, `--color-warning`, `--color-info`, `--color-loading`
- 부드러운 배경: hover, selected, disabled, placeholder
- 경계와 오버레이: `--color-border-*`, `--color-overlay-*`
- 지도 캔버스: `--color-map-*`, `--color-source-*`

아래는 구조를 보여주는 대표 토큰이다. 전체 목록과 현재 값의 원본은 `frontend/src/styles.css`다.

```css
:root {
  --color-bg-page: #edf2ee;
  --color-bg-surface: #fff;
  --color-text-primary: #17211d;
  --color-text-secondary: #69756f;
  --color-text-on-solid: #fff;

  --color-focus: #178459;
  --color-action-primary: #172f25;
  --color-action: #176f4d;
  --color-action-hover: #0f7a4d;
  --color-brand-accent: #18845a;

  --color-bg-hover: #f4f8f5;
  --color-bg-selected: #eaf6ef;
  --color-border-input: #d7dfda;
  --color-error: #b32d2d;
  --color-warning: #a66a18;
  --color-info: #2878d4;

  --color-source-partner: #18845a;
  --color-source-police: #f2b825;
  --color-map-radius-stroke: #13845a;
  --color-map-radius-fill: #31a979;
}
```

카카오맵 SDK에 객체나 SVG 문자열로 전달해야 하는 색상도 `frontend/src/lib/theme.ts`를 통해 같은 CSS 변수를 읽는다. 따라서 향후 테마를 만들 때 CSS 토큰만 바꾸면 일반 UI와 지도 표현이 함께 바뀐다.

현재는 **색상과 색상을 포함한 그림자만 토큰화되어 있다.** 간격·radius·타이포그래피 크기 토큰은 아직 구현하지 않았다. 토큰 추가가 필요하면 기존 토큰으로 표현할 수 없는 이유를 먼저 확인하고, 일회성 색상값을 컴포넌트에 직접 추가하지 않는다.

### 개발용 테마 비교

Vite 개발 서버에서만 화면 오른쪽 아래에 작은 테마 선택기를 표시한다. 선택한 값은 같은 브라우저에 저장되며 일반 UI와 지도 색상에 함께 적용된다.

- `Warm`: 밝은 아이보리와 부드러운 갈색
- `Cocoa`: 짙은 갈색과 절제된 크림색
- `Modern`: 아이보리와 진한 갈색에 코랄을 제한적으로 사용한 균형형

이 기능은 최종 브랜드 방향을 비교하기 위한 도구다. 배포 빌드에는 선택기를 표시하지 않으며, 세 안 중 하나를 최종안으로 확정한 뒤 기본 토큰에 반영하고 비교용 코드는 제거한다.

## 4. 색상 사용 규칙

- `primary`는 주요 행동, 선택 상태, 핵심 강조에 사용한다.
- 오류는 `error`, 주의가 필요하지만 실패가 아닌 상태는 `warning`을 사용한다.
- 연계기관과 경찰관서 색상은 데이터 출처 구분에만 사용한다.
- 색상만으로 상태를 전달하지 않는다. 텍스트, 아이콘, 모양 중 하나를 함께 사용한다.
- 지도 위 오버레이는 지도를 가리지 않도록 반투명 배경과 짧은 문장을 사용한다.
- 새 색상을 쓰기 전 일반 텍스트는 WCAG AA 명암비 4.5:1, 큰 텍스트와 UI 경계는 3:1 이상인지 확인한다.

## 5. 타이포그래피

- 한 화면의 제목 단계는 `h1` → `h2` 순서를 유지한다.
- 본문과 상태 메시지는 12px 미만으로 만들지 않는다. 지도 SDK 내부처럼 제약이 있는 경우에만 예외를 둔다.
- 영문 대문자 kicker는 보조 정보다. 핵심 정보를 대신하지 않는다.
- 긴 기관명·주소·물품명은 레이아웃을 깨지 않게 줄바꿈하거나 말줄임 처리하되, 중요한 원문을 영구히 숨기지 않는다.

> [결정 필요: DS-02] 웹폰트 제공 방식
>
> - 현재 구현: 사용자의 기기에 Pretendard 또는 Noto Sans KR이 있으면 사용하고, 없으면 시스템 글꼴 사용
> - 권장안: MVP에서는 시스템 글꼴 폴백을 유지해 초기 로딩을 가볍게 한다.
> - 결정 영향: 브랜드 일관성과 초기 로딩 성능 사이의 선택이 필요하다.

## 6. 간격·레이아웃·반응형

- 기본 간격은 4px 배수 토큰을 사용한다.
- 데스크톱은 전체 화면 지도를 바탕으로 사용하고 검색·목록 패널만 왼쪽에 띄운다.
- 모바일은 검색·목록 다음에 지도를 세로로 배치하며 지도는 화면 가장자리까지 연결한다.
- 화면 폭 820px 이하를 현재 모바일 기준점으로 사용하되, 특정 기기명보다 내용이 깨지는 지점을 기준으로 조정한다.
- 모바일에서 가로 스크롤이 생기면 안 된다.
- 지도는 모바일에서도 의미 있게 조작할 수 있는 높이를 확보한다.
- 구분선은 정보 묶음이 모호할 때만 사용하고, 우선 여백으로 그룹을 구분한다.

## 7. 공통 요소 상태

모든 입력·버튼·목록 항목은 필요한 상태를 갖는다.

- 기본, hover, focus-visible, active
- disabled
- loading
- error
- selected(선택 가능한 항목인 경우)

키보드 포커스는 제거하지 않는다. 클릭 가능한 영역은 모바일에서 최소 44×44px를 목표로 한다. 애니메이션은 `prefers-reduced-motion`을 존중한다.

## 8. 아이콘·이미지

- 의미 전달이 필요한 아이콘에는 접근 가능한 이름을 제공한다.
- 장식용 아이콘은 스크린 리더에서 숨긴다.
- 습득물 이미지가 없을 때는 현재처럼 카테고리 아이콘과 출처를 표시한다.
- 외부 아이콘 라이브러리는 기존 요소로 표현하기 어려울 때만 도입한다.

> [결정 필요: DS-03] 습득물 이미지 및 빈 상태 일러스트 사용
>
> - 현재 구현: 카테고리 이모지 기반 placeholder, 별도 빈 상태 일러스트 없음
> - 권장안: 실제 이미지 제공 가능 여부가 확정되기 전까지 placeholder를 유지한다.
> - 결정 영향: 카드 높이, 저작권·출처 관리, 로딩 실패 상태가 달라진다.

## 9. 변경 체크리스트

- 기존 토큰으로 표현했는가?
- 정보 위계가 제목 → 설명 → 행동 순으로 분명한가?
- loading, empty, error, disabled, selected 상태를 확인했는가?
- 색상 없이도 상태를 이해할 수 있는가?
- 키보드 포커스가 보이는가?
- 모바일과 데스크톱에서 직접 확인했는가?
- 변경하지 않은 화면 영역에 시각적 회귀가 없는가?
