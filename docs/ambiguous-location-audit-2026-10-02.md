# 동명 보관기관 연결 결과 — 2026-10-02

## 실제 운영 DB 반영 결과

| 항목 | 물품 수 |
| --- | ---: |
| 이번 조사 대상 ambiguous | 2,186 |
| 기관 연결 완료 | **1,960 (89.66%)** |
| 추가 확인 필요 | **226 (10.34%)** |

상세 API는 2,186건 모두 조회에 성공했다. 연결 규칙 369개를 등록했고,
242개 보관기관에 물품을 연결했다. unresolved 226건은 모두 경찰관서 물품이다.

전체 DB는 matched 287,404건, ambiguous 226건, unmatched 440건이다.
이번 작업은 ambiguous를 대상으로 했고 unmatched 440건은 조사 대상에 포함하지 않았다.
이 수치는 반영 직후 조회 결과이며 이후 일일 수집·보존기간 정리로 바뀔 수 있다.

## 어떤 근거로 연결했나

| 검증 방법 | 규칙 수 | 연결한 물품 수 |
| --- | ---: | ---: |
| 장소명 후보 중 상세 전화번호가 정확히 일치하는 기관이 하나 | 156 | 717 |
| 상세 소속 경찰서와 장소명을 함께 대조해 기관이 하나 | 210 | 1,168 |
| 공식 기관 페이지로 관할 변경·지역을 추가 확인 | 3 | 75 |
| 합계 | **369** | **1,960** |

전화번호는 여러 기관이 함께 쓰거나 변경될 수 있어서 단독 식별자로 삼지 않았다.
실제 연결 키는 **API 출처 + 정규화한 목록 보관장소명 + 상세 API 기관 코드(orgId)**다.
상세 orgId가 소속 경찰서 코드인 경우에도 장소명을 함께 쓰므로 경찰서 아래 여러 파출소를 구별한다.
상세 depPlace가 목록 장소 대신 소속 경찰서로 출력되는 경우도 확인했다.

일반 규칙은 같은 이름 후보 중 하나로 좁혀졌을 때만 만들었다.
해당 기관의 DB 주소를 카카오 주소 검색 결과와 대조했고,
DB 좌표와 주소 검색 좌표가 300m 이내인 기관만 채택했다.
주소 검색에 실패한 3개 기관에 관한 15건은 연결을 보류했다.
300m 검사는 좌표 오류를 걸러내는 조건이며, 기관 확인은 전화번호·소속 경찰서 근거로 수행했다.

## DB에 무엇을 저장했나

- `found_items`: 상세 기관 코드·기관명·상세 보관장소·전화번호·조회 시각 5개 필드.
- `storage_location_detail_mappings`: 검증된 369개 연결 규칙과 근거.
- `storage_locations`: 고성경찰서 2곳의 주소와 좌표 수정.
- DB 트리거: 기존 수집 코드가 재수집해도 저장된 상세 근거로 연결을 유지.
  목록 장소가 바뀌면 이전 상세 근거를 지우고, 비활성 기관·모르는 코드는 연결하지 않는다.

새 Python 수집 코드는 상세 정보를 재사용하고, 신규 ambiguous의 상세 API를 조회한다.
일일 수집에서는 상세 조회에 공통 20초 예산을 둬 목록 저장을 지나치게 지연시키지 않는다.
미조회 건은 DB에 ambiguous로 저장하고 다음 실행에서 보충한다.
**DB 반영은 완료됐지만 새 Python 수집 코드의 운영 반영에는 PR 병합·배포가 필요하다.**
