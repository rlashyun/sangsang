# RETRIEVER UI 패턴

> 2026-11-08 UI 개편 목표. PRD가 우선이며 시각 기준은 design-system.md, 구현 기준은 frontend-guidelines.md를 따른다.
> 현재 main에는 기존 검색/반경/스크롤 목록과 사진·상세 기능이 있다. 아래 새 탭·번호 페이지·반경 정책·알림/수령 안내는 구현 예정이며 문서 갱신이 코드 완료를 의미하지 않는다.

## 1. 화면과 상태의 연결

장소 검색 → 후보 위치 미리보기 → 이 장소 선택하기 → 주변 습득물 → 물품 검색 → 상세 → 수령 안내 순서다. 찾는 물건이 없으면 반경 확장 또는 새 물건 알림으로 이어진다. 물품 검색은 항상 선택 위치의 기관 범위 안에서 한다.

상단은 RETRIEVER 로고 바로 오른쪽에 물건 찾기/새 물건 알림, 오른쪽 끝에 이용안내를 둔다. 알림 메뉴 앞에는 이모지를 넣지 않는다. 탭을 이동하거나 창을 닫아도 기존 장소·제출 검색어·반경·페이지를 유지한다.

## 2. 장소 검색과 후보 카드

- 첫 화면: “어디서 잃어버렸나요?”와 장소명/주소 입력, 짧은 설명을 표시한다. 지도 위 검색 패널이 첫 행동을 안내한다.
- 장소 검색 중: 버튼 disabled, 진행 안내와 입력값 유지. 0건과 API 오류를 구분한다.
- 후보: 원문 장소명·주소를 표시하고 주소 아래에 중간 단계 카테고리 태그를 둔다. 초기 장소 카드의 전화번호는 생략하며 연락이 필요한 보관기관 전화번호는 물품 상세에서 제공한다(2026-11-08 변경).
- 분류 태그는 `category_name`을 `>`로 나눈 두 번째 단계만 표시한다. “지하철,전철”은 “지하철”로 표현한다. “여가시설”, “주거시설”처럼 표시하며 `#`, 대분류, 노선명은 붙이지 않는다. 경로가 짧으면 사용 가능한 마지막 분류를 사용하고 값이 없으면 태그를 생략한다.
- 장소 카드 전체를 마우스 올림 또는 키보드 초점으로 강조한다. 누르면 지도를 확대하고 기관 핀보다 큰 흰색 핀으로 위치를 보여준다. 미리보기/확정한 위치의 흰색 핀에는 번호 대신 작은 파란 점만 표시한다. 지도 장소 핀도 같은 미리보기 동작이다. 미리보기 중인 카드에만 “이 장소 선택하기” 버튼을 표시하고 카드 높이는 유지한다. 이 버튼으로 확정한 뒤 물품 검색으로 전환한다. 미리보기 중에는 물품을 조회하지 않고 기관 핀 클릭으로 확정 단계를 건너뛰지 않는다. 새 장소 검색/다시 찾기는 미리보기를 초기화한다.
- 장소 후보는 페이지당 4곳으로 고정한다. 마지막 페이지만 남은 개수를 표시하며 카드 높이는 페이지/선택 전후에 동일하다. 카드 영역 스크롤 없이 아래 이전·번호·다음으로 이동하고 지도에는 현재 페이지 후보만 동일한 전체 순번으로 표시한다. 제목·주소는 한 줄 말줄임하며 전체 내용은 title과 지도 미리보기에서 확인한다. 페이지 이동은 추가 API 호출 없이 미확정 장소만 해제하고, 새 검색/장소 다시 찾기는 첫 페이지로 돌아간다. 데스크톱의 낮은 창에서는 결과 상단과 글씨 간격을 줄여 4개를 유지한다. “페이지당 4곳” 문구는 표시하지 않는다.

장소 확정 후 기본 구조 적용(2026-11-08): 상단에 작은 “‹ 장소 다시 찾기” 텍스트 버튼, 장소 제목 한 번, 주소, 현재 반경을 표시한다. 중복 FOUND ITEMS/장소 제목과 상단 반경 선택기는 제거했다. 다시 찾기는 기존 검색어·후보·장소 페이지를 유지한 채 장소 확인으로 돌아간다. 물품 카드/물품 번호 페이지/알림 입력 화면은 이 단계에 포함하지 않는다.

## 3. 탐색 반경과 기관 범위

### UX-01 — 기본 범위와 수동 확장 (2026-11-08 변경)

- 장소 선택 시 기본 반경 1km다. 결과 하단에서 이전 단계로 돌아갈 수 있다. 두 방향이 모두 가능하면 ‘돌아가기’와 ‘넓혀보기’를 나란히 둔다.
- 장소만 선택했을 때 일반 확장 안내는 숨긴다. 사용자가 물품 검색을 제출한 뒤 결과 아래에 “찾는 물건이 없나요?”와 다음 반경 버튼/새 물건 알림 받기를 제공한다.
- 반경은 1→1.5→2km다. 1km에서는 “1.5km로 넓혀보기”, 1.5km에서는 “2km로 넓혀보기”, 2km에서는 추가 확장 버튼을 숨긴다.
- 확장을 누르면 장소와 마지막으로 제출한 검색어를 유지해 즉시 재검색한다. 입력 중인 미제출 문구와 혼동하지 않는다. 결과는 첫 페이지로 돌아가고 지도·기관·목록 범위가 함께 변경된다.
- 검색 결과가 0건이라는 이유만으로 반경을 자동 확장하지 않는다.

### UX-02 — 기관 0곳의 예외 (2026-11-08 변경)

- 기관 조회가 정상 완료된 뒤 1km 안에 기관이 0곳이면 1→1.5→2km 순서로 최대 2km까지 자동 확장한다. 물품 검색 전에도 적용한다.
- “1km 안에 보관기관이 없어 1.5km로 넓혔어요.”를 같은 상태 영역에 표시한다. 2km로 다시 넓히면 “1.5km 안에 보관기관이 없어 2km로 넓혔어요.”를 표시한다. 표시 반경과 알림에 넘길 조건도 최종 반경으로 바꾼다.
- 1.5km도 0곳이면 2km로 넓혀 다시 확인한다. 2km도 0곳이면 자동 확장을 멈추고 기관 없음과 장소 다시 찾기를 안내한다. 기관이 있는 단계에서 확장을 멈춘다. 기관이 없어도 물품 검색을 제출할 수 있는 상태를 두고, 검색 후 알림 진입을 제공한다. 최대 2km에서는 추가 확장 버튼을 숨긴다. 빈 기관 ID로 무의미한 API 요청은 보내지 않는다.
- 기관 조회 실패나 로딩, 물품 0건은 기관 0곳으로 취급하지 않는다.

기관 핀을 선택하면 해당 기관 목록임을 제목으로 알리고 “선택 반경 전체” 복귀를 유지한다. 선택 반경 밖 기관이 섞이면 안 된다. 기관 선택 상태에서 반경을 변경하면 기관 단독 선택을 해제하고 새 반경 전체에서 재검색한다.

지도 반경은 강한 원 테두리 대신 은은한 파란 면이 바깥으로 옅어지는 표현을 사용한다. 현재 반경을 텍스트로 보여주고 거리 필터는 정확하게 유지한다.

## 4. 습득물 목록과 검색

장소 선택 후 별도 물품 검색 없이 현재 범위의 최근 등록 목록을 표시한다. 카드에는 사진·카테고리·원문 명칭·보관장소·등록일과 색상 태그를 표시한다. 색상 태그는 카테고리 바로 뒤에 붙이고, 값이 있을 때 색 이름만 표시하며 “색상” 접두사는 붙이지 않는다. `item_name`은 원문 그대로 사용하고 색상을 이름에 덧붙이지 않는다. 원문 설명은 카드에서 빼고 상세 본문에 표시한다. 확장 결과의 색상 옆에는 직전 반경 내 보관기관의 물품에만 ‘1km 이내’ 또는 ‘1.5km 이내’를 표시한다. 2km에서는 이전 1.5km 안의 모든 물품에 같은 표식을 붙인다.

사진은 `image_url`의 원본을 고정 영역 안에 전체가 보이도록 표시한다. 지연 로딩과 비율을 유지하고, 빈 URL·기본 그림(`img02_no_img.gif`)·로드 실패는 카테고리별 대체 이미지로 처리한다. 로딩 때문에 카드 위치가 바뀌면 안 된다.

검색어 상한 30자와 앞뒤 공백 제거는 유지한다. 새 요청에서 오래된 응답이 결과를 덮어쓰지 않도록 취소/요청 순서를 보호한다. 검색 후에도 카드 정보 배치는 그대로 두고 유사도 높은 순으로만 확인한다. 점수·%·임시 배지를 표시하지 않는다. % 환산은 요청하지 않고 검색 결과의 정렬 순서를 페이지를 넘겨도 유지한다. 내부 점수와 원문 데이터는 임의로 변형하지 않는다.

### 번호 페이지와 카드 배치

- 장소/물품 목록은 긴 스크롤이나 더 보기 버튼 대신 작은 이전·페이지 번호·다음 버튼으로 이동한다.
- 장소와 물품 모두 페이지당 4개로 고정한다. 마지막 페이지만 남은 개수를 표시한다. 카드 목록, 페이지 영역, 검색 후 확장/알림 영역은 별도 공간을 확보한다.
- 긴 명칭·주소·보관장소와 사진이 카드 경계를 넘지 않도록 한다. 제목이 잘리면 상세에서 원문 전체를 확인할 수 있어야 한다.
- 새 검색/범위 변경 시 첫 페이지로 이동한다. 페이지 이동만으로 검색 조건을 초기화하지 않는다.
- 서버의 기존 50건 커서는 UI 페이지 번호와 다르다. 아직 받지 않은 결과·전체 페이지를 임의로 만들어 표시하지 않는다. 기본 목록은 필요한 화면 페이지까지 기존 50건 커서를 이어 받고 검색 결과는 받은 순서대로 나눈다. 후속 검색 API 변경은 별도로 협의한다.

0건은 “현재 조건에 해당하는 습득물이 없어요.” 또는 “'검색어'와 유사한 습득물이 없어요.”로 구분한다. 기관 없음과 물품 없음, API 오류를 따로 안내한다. 검색 후 0건에서도 수동 확장과 새 물건 알림 진입점을 유지한다.

## 5. 상세 창과 수령 안내

2026-11-09 로컬 적용: 상세 전체 너비의 하단 중앙 확인 질문에서 같은 dialog 안의 수령 안내로 전환한다. 안내 제목으로 포커스를 이동하고 “물품 정보 다시 보기”는 상세 스크롤과 확인 버튼 포커스를 복원한다. “아니요, 더 찾아볼게요”와 “확인했어요”는 목록의 원래 카드로 돌아가며 검색어·반경·페이지를 유지하고 API를 재조회하지 않는다. 출처는 사진 아래의 작은 “등록 정보 출처” 문구로 옮기고 주요 속성에서 제외했다.

현재 main의 상세 창·사진·기관 ID 연결·포커스 복귀·Esc/바깥 클릭/뒤로가기 처리를 재사용한다. 목록 갱신 중에는 기존 카드 상세 열기를 비활성화하고, 상세가 열리면 배경 조작·스크롤·포커스 이탈을 막는다.

개편 목표는 배경을 흐리게 한 흰색 둥근 안내 창이다. 노션식 문서처럼 상단 사진/명칭/속성, 아래 원문 설명과 보관 위치를 배치한다. 상세 사진은 데스크톱 340px/모바일 240px 고정 높이 안에서 원본 전체를 보여주고, 물품명·기본 속성·설명·보관기관은 오른쪽에 모은다. 모바일에서는 사진 아래로 이어진다. 설명 줄바꿈을 유지한다. 사진·분류·색상·등록일·출처·검증된 기관명/주소/연락처를 사용한다. 기관 연락처는 `storage_location_id`가 같은 기관에서만 연결한다. 누락값은 정보 없음, 명칭 누락은 이름 미상으로 표시한다. 보관기한 등 없는 정보는 만들지 않는다.

- 질문: “찾으시는 물건이 맞나요?”
- 아니요: “아니요, 더 찾아볼게요”로 닫고 이전 검색·페이지·카드 포커스를 복원한다.
- 예: “예, 수령 방법 보기”로 안내 창을 연다. 본인 인증이나 소유 확인 완료로 처리하지 않는다.
- 수령 안내: 기관 사전 연락(보관 여부/장소/시간/관리번호) → 신분증과 물품 특징 준비 → 기관 확인 후 수령.
- 대리 수령·신분증 분실 시 준비물은 기관에 미리 확인하도록 한다. 이관 가능성 때문에 방문 전 연락을 안내한다.
- 최종 버튼은 “확인했어요”이며 수령 안내를 닫고 기존 목록으로 돌아간다. 수령 예약/배송/반환 신청은 추가하지 않는다.

## 6. 새 물건 알림

검색 결과 하단에서 새 물건 알림 받기를 선택하면 상단 알림 탭이 활성화되고 배경 지도/검색은 흐려진다. 검색 패널보다 넓고 모서리가 둥근 흰색 창에 왼쪽 조건 요약·오른쪽 이메일을 배치한다.

요약에는 장소/주소, 좌표에 대응하는 선택 장소, 현재 반경, 제출 검색어, 알림 기간을 표시한다. 위치와 물품을 다시 입력하게 하지 않는다. 알림 조건 수정은 같은 창에서 반경(1·1.5·2km)만 편집하고 적용/취소한다. 장소·제출 물품명과 7일 기간은 고정하며 장소나 물품 변경은 검색 화면에서 다시 검색한다. 반경 변경은 알림에만 적용한다. 취소/닫기는 이전 검색 결과를 유지한다. 직접 탭 진입 시 조건이 없으면 먼저 검색하도록 안내한다.

- 버튼: “이 조건으로 알림 받기”.
- 신청 후: “메일의 확인 링크를 누르면 알림이 활성화돼요.” 이메일 확인 전 발송하지 않는다.
- 안내: “등록 다음날부터 7일간, 매일 데이터 갱신 후 새 유사 물품이 있으면 알려드려요.”
- 유사 물품이 없는 날에는 결과 메일을 보내지 않는다. 결과 메일은 7회로 고정하지 않는다.
- 마지막 날에는 결과가 없어도 종료·연장 안내를 보낸다. “이번 알림은 종료되며 이후에는 메일이 발송되지 않아요. 계속 받고 싶다면 연장해 주세요.”
- 기간은 한국시간 등록일 D 기준 D+1~D+7이다. 늦은 이메일 확인/실패 재시도/연장 기간 세부 처리는 담당자 협의 대상으로 남긴다.
- 예약 이후 새 물품만 비교하고 이미 보낸 물품은 다시 보내지 않는다. 해지 링크와 종료 상태를 제공한다.

상태는 입력 오류, 신청 중, 확인 메일 발송 성공/실패, 확인 대기, 활성, 종료, 해지, 링크 만료를 구분한다. 이메일 오류/서버 오류에서 입력한 검색 조건을 유지한다. 데모에서는 실제 메일을 보냈다고 오인시키지 않는다.

## 7. 이용안내와 반응형

이용안내는 한 페이지로 서비스 소개, 물건 찾기 탭의 장소 선택→물품 검색→확장→수령 안내, 새 물건 알림 탭의 조건 확인→메일 확인→갱신 후 알림을 짧게 설명한다. 지원하는 6개 카테고리와 기관 사전 연락을 안내한다. 장문의 FAQ/회원가입 화면을 추가하지 않는다.

820px 이하에서는 지도를 위에 두고 장소·습득물 검색을 화면 하단 패널에 배치한다. 손잡이를 위아래로 끌거나 눌러 펼치고 줄이며, 검색 입력에 초점을 맞추면 펼쳐진다. 결과와 페이지 이동은 패널 안에서 스크롤해 확인한다. 상세 하단 시트는 유지한다.

로그인·마이페이지는 이번 알림에 필요하지 않다. 기존 UX-04/UX-05의 회원 기능 후보는 후속 검토로 남기고 이번 이메일 예약을 차단하지 않는다.

## 8. 공통 상태와 검수

초기/로딩/성공/빈 결과/오류/disabled/선택을 구분하고 같은 영역에서 상태를 알린다. `role="status"`, `aria-live="polite"`, 입력 label, 시맨틱 버튼/목록, 키보드 포커스를 유지한다. 지도에만 핵심 정보를 의존하지 않는다.

1. 장소 성공/0건/오류와 전화번호·분류 누락을 확인한다.
2. 긴 장소명과 물품명, 사진 로딩/없음/실패가 카드/페이지와 겹치지 않는지 본다.
3. 창 높이가 작아져도 페이지와 검색 후 확장/알림 버튼이 남는지 확인한다.
4. 기관이 있는 1km는 유지되고, 0곳일 때만 1→1.5→2km 순서로 최대 2km까지 자동 확장되는지 확인한다. 1.5km도 0곳이면 2km로 확장되고 2km도 0곳이면 멈추는지, API 오류와 물품만 0건인 경우 자동 확장하지 않는지도 확인한다.
5. 검색 전 수동 확장 안내가 숨겨지고 검색 후 표시되는지 확인한다.
6. 1→1.5→2km 수동 확장 및 2→1.5→1km 축소에서 제출 검색어 유지·즉시 재검색·첫 페이지 이동을 확인한다. 직접 줄인 범위에 기관이 없어도 그 반경을 유지한다.
7. 상세/수령/알림 창의 키보드, 닫기, 뒤로가기, 검색 조건/페이지/포커스 복귀를 확인한다.
8. 알림에 마지막 반경과 제출 검색어가 전달되고, 확인 전 미발송·없는 날 건너뛰기·최종 종료 메일을 구분하는지 확인한다.
9. 기존 모바일 동작, 느린 응답/요청 역전, 데이터 오류를 확인한다.

2026-11-09 로컬 알림 UI 적용: 물품 검색 후 결과 하단에 다음 반경 확장과 새 물건 알림 받기를 나란히 제공하고, 최대 반경에서는 ‘돌아가기’와 알림을 표시한다. 상단 새 물건 알림도 같은 창으로 연결한다. 선택 장소·현재 반경·마지막 제출 검색어를 읽기 전용으로 전달하고 입력 중인 검색어는 사용하지 않는다. 조건이 없으면 먼저 검색하도록 안내한다. 닫기/Esc/뒤로가기는 기존 검색·페이지·포커스를 복원한다. 이메일은 브라우저 형식을 검증하되 API 연결 전 미리보기임을 항상 표시하고, 제출해도 저장/확인 메일 발송 성공으로 처리하지 않는다. 예약 저장·이메일 확인·스케줄러·발송은 미구현이다.
