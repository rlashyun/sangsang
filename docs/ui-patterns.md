# 리트리버 UI 패턴

> 상태: 초안
>
> 이 문서는 사용자가 화면에서 무엇을 보고 어떤 순서로 행동하는지 정의한다. 시각 값은 `docs/design-system.md`, React 구현은 `docs/frontend-guidelines.md`를 따른다.

## 1. 핵심 사용자 흐름

리트리버의 기본 흐름은 다음 순서를 유지한다.

1. 사용자가 잃어버린 장소명 또는 주소를 검색한다.
2. 장소 후보에서 주소를 확인하고 하나를 선택한다.
3. 선택 지점과 반경, 범위 안의 보관기관을 지도에 표시한다.
4. 해당 기관들이 현재 보관 중인 습득물을 목록으로 보여준다.
5. 사용자가 물품 검색어를 입력해 현재 공간 범위 안에서 결과를 좁힌다.
6. 지도 핀을 선택하면 해당 기관의 물품만 보고, 다시 선택 반경 전체로 돌아갈 수 있다.

검색의 순서는 반드시 **장소 선택 → 공간 범위 결정 → 물품 검색**이다. 전국 단위 물품 검색처럼 보이는 UI를 만들지 않는다.

## 2. 장소 검색

### 초기 상태

- 제목, 짧은 설명, 장소명·주소 입력창, 검색 버튼을 보여준다.
- 지도에는 전체 기관을 보여주되, 사용자가 먼저 해야 할 행동은 장소 검색임을 분명히 한다.
- 현재 지원 카테고리와 데이터 갱신 시각 고지는 제품 결정 후 추가한다.

### 검색 중

- 버튼을 disabled 처리하고 중복 제출을 막는다.
- 기존 화면 위치에서 “카카오맵에서 위치를 찾고 있습니다…” 상태를 알린다.
- 이미 입력한 검색어는 유지한다.

### 검색 결과

- 후보마다 이름, 주소, 가능한 경우 전화번호와 카테고리를 표시한다.
- 후보 전체 영역을 버튼으로 만들어 키보드와 터치로 선택 가능하게 한다.
- 같은 이름의 장소를 구분할 수 있도록 주소를 생략하지 않는다.

### 0건·오류

- 0건: 더 구체적인 장소명이나 주소를 입력하라고 안내한다.
- 오류: 사용자가 이해할 수 있는 한국어 메시지를 표시하고 입력값을 유지해 재시도할 수 있게 한다.
- 0건과 시스템 오류를 같은 메시지로 처리하지 않는다.

## 3. 탐색 범위 선택

- 장소를 선택하면 장소명, 주소, 반경, 기관 수를 요약한다.
- 지도에는 선택 지점, 반경 원, 범위 안 기관만 보여준다.
- “장소 다시 찾기”는 장소 후보, 선택 범위, 물품 결과를 초기화한다.
- 기관 핀을 선택하면 목록 범위가 해당 기관으로 좁혀졌음을 제목에서 분명히 표시한다.
- 기관 범위에서는 “선택 반경 전체”로 돌아가는 행동을 제공한다.

> [결정 완료: UX-01 — 2026-09-27] 반경 1·3·5km 선택 방식
>
> - 현재 구현: 1km 고정
> - 결정: 장소 선택 직후 1km를 기본으로 적용한다.
> - 결정: 현재 탐색 범위 영역에 1km·3km·5km 선택 버튼을 항상 표시한다.
> - 결정: 반경은 사용자가 버튼을 눌렀을 때만 변경하며 결과 수에 따라 자동으로 변경하지 않는다.
> - 구현 상태: 미구현

> [결정 완료: UX-02 — 2026-09-27] 반경 내 기관이 0곳일 때의 다음 행동
>
> - 현재 구현: 등록된 기관이 없다는 지도 메시지와 빈 물품 상태 표시
> - 결정: 선택 반경을 자동으로 확장하지 않는다.
> - 결정: 더 넓은 반경이 있으면 사용자가 직접 선택할 수 있는 확장 버튼을 빈 상태에 표시한다.
> - 결정: 기존 “장소 다시 찾기” 행동도 유지한다.
> - 구현 상태: 미구현

## 4. 습득물 탐색

### 기본 목록

- 장소 선택 직후 별도 검색 없이 현재 범위의 습득물을 불러온다.
- 카드에는 물품명, 원분류, 색상, 설명, 보관장소, 등록일, 출처를 표시한다.
- API 원문을 화면에서 임의로 고쳐 쓰지 않는다.
- 내부 유사도 점수는 사용자에게 표시하지 않는다.

### 검색

- 물품 검색은 현재 선택된 기관 ID 범위 안에서만 실행한다.
- 검색어는 공백을 제거한 뒤 전송한다.
- PRD 기준 최대 30자를 클라이언트와 서버에서 함께 적용한다.
- 검색 중 버튼을 disabled 처리하고 진행 상태를 알린다.
- 새 요청이 시작되면 오래된 요청이 최신 결과를 덮어쓰지 않게 한다.

### 0건·오류

- 검색어가 없을 때 0건: “현재 조건에 해당하는 습득물이 없습니다.”
- 검색어가 있을 때 0건: “'검색어'와 유사한 습득물이 없습니다.”
- 연결된 기관이 없을 때: 기관 없음과 물품 없음의 원인을 구분해 안내한다.
- 오류: 결과를 비우고 로딩 실패 메시지를 표시하되 다시 검색할 수 있게 한다.

## 5. 지도와 목록의 관계

- 지도 핀, 정보창, 목록 제목은 같은 기관 범위를 가리켜야 한다.
- 여러 기관이 같은 좌표에 있으면 한 위치에 묶고 기관 수를 알린다.
- 지도 핀 클릭만으로 얻을 수 있는 핵심 정보가 없어야 한다. 기관명, 주소, 물품 목록은 텍스트 영역에서도 확인 가능해야 한다.
- 지도 로딩 실패와 기관 데이터 로딩 실패를 구분한다.
- 기관 수·물품 수를 가져오지 못해도 장소 검색과 지도 탐색 자체는 가능한 범위에서 유지한다.
- 지도 위 상태 배지는 한 줄을 우선하며, 모바일에서 지도 조작 버튼을 가리지 않는다.

## 6. 공통 비동기 상태

각 기능은 다음 상태를 빠짐없이 설계한다.

| 상태 | 사용자에게 보여줄 것 | 행동 원칙 |
| --- | --- | --- |
| 초기 | 다음 행동을 설명하는 짧은 안내 | 자동으로 오류처럼 보이지 않게 한다 |
| loading | 무엇을 불러오는지 설명 | 중복 요청 버튼은 disabled 처리한다 |
| success | 결과 수와 현재 범위 | 지도와 목록의 범위를 일치시킨다 |
| empty | 0건인 이유와 가능한 다음 행동 | 결과가 없다는 사실을 실패로 과장하지 않는다 |
| error | 한국어 오류와 재시도 가능한 상태 | 입력과 이미 확인한 맥락을 가능한 유지한다 |
| disabled | 사용할 수 없는 이유가 화면 맥락에서 드러남 | 색상·opacity만으로 설명하지 않는다 |

## 7. 반응형 동작

### 데스크톱

- 검색·결과 패널과 지도를 나란히 둔다.
- 결과 목록만 내부 스크롤하고 지도는 화면 높이를 유지한다.
- 선택 결과를 보면서 지도를 동시에 조작할 수 있어야 한다.

### 모바일

- 검색·결과를 먼저, 지도를 그다음에 배치한다.
- 입력창과 버튼이 좁아져도 텍스트가 잘리거나 가로 스크롤이 생기지 않아야 한다.
- 목록과 지도 각각 충분한 높이를 갖게 한다.
- 모바일에서도 지도 핀 선택 후 기관 범위와 전체 반경 사이를 이동할 수 있어야 한다.

> [결정 필요: UX-03] 모바일에서 지도와 목록의 우선순위
>
> - 현재 구현: 검색·목록 위, 지도 아래의 세로 배치
> - 권장안: MVP에서는 현재 배치를 유지하고, 실제 사용 관찰 후 지도/목록 탭 또는 bottom sheet를 검토한다.
> - 결정 영향: 모바일 탐색 속도와 구현 복잡도가 크게 달라진다.

## 8. 로그인·마이페이지 예정 범위

로그인과 마이페이지는 현재 구현되어 있지 않다. 추가하더라도 비로그인 사용자의 장소·물품 탐색을 막지 않는 것을 기본 권장안으로 둔다.

> [결정 필요: UX-04] 로그인이 꼭 필요한 행동
>
> - 권장안: 검색과 지도는 공개하고, 저장·알림처럼 개인 데이터가 필요한 행동에서만 로그인 요청
> - 결정할 내용: 이메일, 소셜 로그인, 익명 사용 가능 범위, 로그인 후 원래 화면 복귀
> - 결정 영향: 인증 제공자와 개인정보 처리 범위가 정해진다.

> [결정 필요: UX-05] 마이페이지의 첫 번째 기능
>
> - 후보: 저장한 검색 조건, 관심 습득물, 알림 설정, 계정 관리
> - 권장안: 사용자가 반복 확인해야 하는 “저장한 검색 조건 + 알림 설정”을 먼저 검증한다.
> - 결정 영향: 필요한 데이터 모델과 알림 채널이 달라지므로 화면 구현 전에 제품 결정을 마쳐야 한다.

## 9. UI 변경 검수 시나리오

1. 첫 진입에서 기관 로딩 성공·실패를 각각 확인한다.
2. 장소 검색 성공, 후보 0건, API 오류를 확인한다.
3. 장소를 선택하고 반경 원·기관 수·물품 목록이 같은 범위인지 확인한다.
4. 물품 검색 성공, 0건, API 오류를 확인한다.
5. 기관 핀 선택 후 해당 기관 목록과 반경 전체 복귀를 확인한다.
6. 버튼 연속 클릭과 느린 응답에서 중복·역전 결과가 없는지 확인한다.
7. 키보드만으로 주요 흐름을 완료한다.
8. 모바일과 데스크톱에서 가로 스크롤, 겹침, 잘림을 확인한다.
