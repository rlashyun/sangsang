# 핸드오프 — 권희준 → 김택수 (2026-09-28)

백엔드·플랫폼 쪽에서 확인·완료한 것을 프런트엔드로 넘깁니다. 셋 다 현재 미구현 상태예요.

---

## [1] 최종 갱신 시각 표시 (PRD 6)

API 필드는 이미 `main`에 병합·배포돼 있어요 (PR #19).

- 위치: `GET /api/institutions` 응답의 `data_updated_at`
- 예시: `"2026-09-27T00:24:53.965651+00:00"` (UTC)
- 타입: `frontend/src/types.ts`의 `InstitutionPayload`(현재 `institutions?`, `counts_available?`, `count_error?`만 있음)에 `data_updated_at?: string | null` 추가

값의 의미
- 연계기관·경찰관서 두 동기화 중 **더 늦게** 반영된 쪽의 완료 시각이에요
- 한쪽이 실패한 날엔 그쪽의 마지막 성공 시각이 나와서 "어제 기준"처럼 보일 수 있는데, 최신이라고 과장하지 않으려고 일부러 그렇게 했어요
- 화면에는 한국 시간으로 바꿔서 보여 주세요

`null`이면 문구를 숨겨 주세요
- 조회가 실패했거나 성공 기록이 없는 경우예요. 이때도 기관 목록은 정상으로 와요

문구는 택수님이 정해 주세요
- 크론은 9시에 시작하지만 끝나는 시각은 정각이 아니에요 (실측: 오전 9시 24분·37분)
- "오늘 오전 9시 기준"으로 고정할지, 실제 시각("오늘 오전 9:24 기준")을 보여 줄지 골라 주세요
- 날짜가 오늘이 아니면 "어제"나 날짜로 보여 줘야 해요
- 이 응답은 CDN에 최대 5분(재검증 포함 최대 15분) 캐시돼서, 크론 직후엔 잠깐 이전 값이 보일 수 있어요

## [2] 검색어 30자 초과 경고 알림 (PRD 3.3)

- `FoundItemBrowser.tsx:113`에 `maxLength={30}`만 있어서, 31번째 글자가 아무 안내 없이 잘려요
- PRD 3.3은 30자를 넘기면 경고 알림을 보여 주라고 되어 있어서 이 알림이 필요해요
- 서버도 31자부터 400으로 막고 있어요 (`"습득물 검색어는 30자 이하여야 합니다."`) — 서버 쪽은 이미 반영되어 있으니 프런트만 남았어요

## [3] 반경 1·3·5km 선택 (P0, PRD 3.1-3·4.2 — D4)

PRD는 "완료 ✅"로 적혀 있지만 실제로는 **1km 고정, 선택 UI 없음** 상태예요. 확인해 보니 이건 **백엔드 변경이 필요 없는 순수 프런트엔드 작업**이라 제 쪽에서 할 게 없어요 — 그래서 코드는 그대로 두고 조사 결과만 넘겨드립니다.

구조 확인 결과
- 반경 필터링은 전부 클라이언트에서 일어나요: `App.tsx`가 선택 지점과 각 기관 사이 거리를 `geo.js`의 `distanceMeters()`로 계산하고, `SEARCH_RADIUS_METERS`(현재 `1000` 고정, `geo.js:1`) 이내인 기관만 걸러서 `location_ids`로 만들어요
- `/api/found-items`·`/api/institutions`는 반경 개념 자체를 몰라요 — `location_ids` 묶음만 받아서 처리하니, **API 계약(파라미터·응답 필드·에러 코드)을 바꿀 필요가 없어요**
- 상수를 참조하는 지점은 3곳: `App.tsx:9,67,74` (필터링), `KakaoMap.tsx:10,104,106,328,340` (지도 원 표시·리셋), `FoundItemBrowser.tsx`는 직접 참조는 없고 `radiusScope` prop만 받음

즉 할 일은:
- `SEARCH_RADIUS_METERS` 상수를 상태값으로 바꾸고 1/3/5km 선택 UI(버튼·드롭다운 등, 디자인은 `docs/design-system.md`·`docs/ui-patterns.md` 참고)를 추가
- 선택값을 `App.tsx`의 필터링 로직과 `KakaoMap.tsx`의 원 반지름·리셋 로직 양쪽에 전달
- 기본값은 지금처럼 1km 유지 권장 (변경 시 알려주시면 저도 맞춰 확인할게요)

테스트 관련 — 손 안 대도 돼요
- `tests/web/test_map_radius.js`는 `SEARCH_RADIUS_METERS`를 참조하지 않고 `distanceMeters()` 정확도(약 1km 거리 계산)와 `markerCountLabel()`만 검증해요. AGENTS.md 9.2에 "D4 구현 시 이 테스트도 손봐야 한다"는 메모가 있는데, 실제로 열어보니 해당 없어요 — 상수를 선택형으로 바꿔도 이 테스트는 그대로 통과할 거예요
- 새 UI에 대한 테스트(선택 상태 변경, 필터링 결과 변화)는 프런트 쪽에서 추가해 주시면 됩니다

우선순위 결정 필요
- UI 형태(버튼 3개 vs 드롭다운 등)와 착수 시점은 아직 미정이에요. 정해지면 알려주세요, 필요하면 같이 확인하겠습니다
