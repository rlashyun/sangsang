## 7. 공용 세션 전환 (2026-11-18 관측 · 2026-11-20 구현)

| 한계 | 지금 미루는 이유 | 다시 볼 조건 | 담당 |
| --- | --- | --- | --- |
| 대화형 검색 세션이 서버 프로세스 메모리에만 있다(`web/agent_api.py`의 `sessions`, 최대 128개·유휴 30분). 요청이 다른 Vercel 인스턴스로 가거나, 새로 배포하거나, 쉬던 인스턴스가 꺼지면 대화 도중 410 `session_expired`("대화가 만료됐어요")가 난다. 취소(`/cancel`)도 스트림이 도는 인스턴스에 닿아야만 동작한다 | 실사용자가 적어 인스턴스가 여러 대로 늘 일이 드물고, 끊겨도 새 대화로 다시 시작하면 된다. 11-21 마감 전에 Agent 결합(김성현, `docs/team-roles.md` 2번)과 같은 파일을 고치는 충돌 위험이 더 크다(2026-11-18 결정) | Vercel 로그에 `/api/search-chat` 410이 보일 때, 사용자가 늘 때, 인스턴스가 여러 대로 느는 것이 관측될 때 | 미정 (착수 전 김성현과 순서 합의) |

2026-11-20: 사용자가 이 한계의 수정을 승인했고 Supabase 공용 저장·유휴 30분을 선택했다. 복구·로그·공용 세션은 PR #66으로 구현·병합했고 운영 DB 적용과 배포 후 대화·재시도·취소·만료 삭제를 확인했다. 사용자 승인과 검증 한계는 `docs/measurements.md`에 기록했으며 아래 상태표 방식은 채택하지 않는다. 최신 계약은 [대화형 검색 문서](agent-search.md)를 따른다.

과거 검토안(2026-11-18, 미채택·이력 보존):

- 대화 상태를 서명한 상태표(`state_token`)로 만들어 응답마다 돌려주고, 브라우저가 다음 요청에 함께 보낸다. 서버는 상태를 저장하지 않으므로 어느 인스턴스가 받아도 대화가 이어진다.
- 서명 키는 모든 인스턴스에서 같아야 한다. 새 환경 변수 없이 서버 전용 비밀값(`OPENROUTER_API_KEY`)에서 파생하는 안을 검토했다. 서명이 맞지 않거나 30분이 지난 상태표는 410으로 거절한다. 상태표는 브라우저로 나가므로 비밀값 자체를 담지 않는다(`AGENTS.md` 키 격리).
- 취소는 `/cancel` 대신 브라우저가 스트림 연결을 끊는다. 취소한 실행의 새 상태표는 받지 않으므로 이전 상태가 그대로 남는다.
- "그 물품 어디 있어?" 같은 질문에 쓰는 물품은 상태표에 넣지 않고 기존 재조회 경로(`find_items_by_id`, 최대 10건)로 다시 읽는다.
- Supabase에 세션 표를 두는 안은 요청마다 DB 호출이 여러 번 늘고, 운영 마이그레이션과 대화 내용 보관·삭제 작업이 필요해 뒤로 미뤘다.
- 고칠 곳: 새 모듈 `web/agent_state.py`, `web/agent_api.py`, `frontend/src/{types.ts,api/client.ts,components/AgentSearchApp.tsx}`, `tests/web/test_agent_api.py`, `docs/agent-search.md`. 먼저 "인스턴스 A에서 시작한 대화를 인스턴스 B가 이어받는다" 테스트를 같은 키 성공·다른 키 410 쌍으로 만들고, 지금 코드에서 실패하는지 확인한다.
- 그 전까지 발표 시연에서는 시연 직전 `main` 병합(배포)을 멈추고, 시작 전에 대화를 한 번 해 둔다.
