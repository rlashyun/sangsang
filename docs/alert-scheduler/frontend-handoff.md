## 2. 예약 화면

### 입력

- 이메일, [필수] 개인정보 수집·이용 동의 — 동의하지 않으면 예약할 수 없다(`consent: true`)
- 검색어는 제출한 물품 검색어 그대로. **1~30자 필수**. 검색어 없이 장소만으로는 받지 않는다
- 장소 1~3곳의 이름·좌표, 반경 하나(1000·1500·2000m)

### 동의 문구에 들어가야 할 내용 (개인정보 보호법 제15조 제2항)

| 항목 | 내용 |
| --- | --- |
| 수집 목적 | 저장한 조건으로 새 유사 습득물을 찾아 이메일로 알림, 종료·연장 안내, 서비스 이용 통계 |
| 수집 항목 | 이메일, 검색어, 기준 장소 이름·좌표, 반경 |
| 보유 기간 | 이메일은 알림이 끝난 다음 날(연장하면 연장된 종료일 다음 날) 삭제. 취소하면 즉시, 확인하지 않으면 24시간 뒤 삭제. **이메일을 지운 뒤에도 검색어·장소·반경은 이메일과 연결되지 않은 상태로 이용 통계(전환율)용으로 남는다**(2026-11-15 결정 — 남기고 동의 문구에 안내한다) |
| 거부 권리 | 동의하지 않을 수 있으며, 이 경우 알림 신청을 할 수 없음. 물건 찾기는 그대로 쓸 수 있음 |

통계 보존 안내 예시 문구(보유 기간 항목에 덧붙인다):

> 알림이 끝나 이메일 주소를 지운 뒤에도 검색어·장소·반경은 이메일과 연결되지 않은 상태로 남겨 서비스 이용 통계에 사용합니다.

### 알림 일정 안내 (PRD 4.3-E)

- 등록일이 D일이면 **D+1부터 D+7까지** 한국시간 달력상 7일. 새 유사 물품이 등록된 날에만 메일이 간다(KST 11시대).
- **D+7에는 결과가 없어도 종료·연장 안내 메일**이 간다. 그날 결과가 있으면 같은 메일에 담긴다. 연장은 그날 밤 12시 전까지 메일 속 링크로 한다(한 번에 +7일, 최대 3회).
- 확인이 늦어도 일정은 등록일 기준이다(확인 링크는 24시간 유효).
- "유사"의 기준은 **같은 검색어로 같은 반경을 검색했을 때 결과에 나오는 물품**이다. 종류만 쓴 검색어(예: "아이폰")는 같은 종류의 새 물품이 모두 알림 대상이 된다.
- **검색어에 색·브랜드·특징(예: 검정, 루이비통, 왼쪽)이 있으면 그 말이 맞는 물품만 알린다**(2026-11-15 사용자 결정). 색을 알 수 없는 물품은 함께 보낸다. 검색 화면 결과보다 좁아질 수 있다. 화면 안내 예시 문구:
  - "색이나 브랜드를 함께 적으면 그 조건에 맞는 물건만 알려 드려요. (예: 검정 반지갑)"

### 예약 성공 후 안내

- 확인 메일을 보냈고, **24시간 안에** 메일 속 링크를 눌러야 알림이 켜진다는 안내
- **확인 메일이 스팸함으로 갈 수 있다는 안내를 눈에 띄게 넣어 주세요.** 특히 Gmail 사용자에게 중요하다(아래 실측). 예시 문구:
  - "Gmail을 쓰신다면 **스팸함**을 꼭 확인해 주세요. 메일이 스팸함에 있으면 '스팸 아님'을 눌러 주세요. 그래야 다음 알림이 받은편지함으로 옵니다."
  - "몇 분이 지나도 메일이 오지 않았다면 스팸함·광고함에서 '리트리버'를 찾아 주세요."
- **발송 테스트 결과 (2026-11-07, 서비스용 Gmail 계정 → 받는 곳별 1통씩)**

  | 받는 곳 | 도착한 곳 | 발신자 표시 |
  | --- | --- | --- |
  | 네이버 메일 | 받은편지함 | 리트리버 |
  | Gmail | **스팸함** | 리트리버 |

  - 새 계정이라 Gmail 쪽 평판이 아직 없어서인 것으로 본다. 발신 수단은 Google 메일(Gmail SMTP)로 확정했다(2026-11-22). Resend로 옮기지 않으므로 위 안내 문구를 화면에 유지하고, 배포 전 `send_test`로 스팸함 분류를 다시 확인한다.

### 오류 상태

서버가 돌려주는 한국어 `error`를 그대로 보여 주면 된다.

| 코드 | 언제 | 화면 |
| --- | --- | --- |
| 400 | 이메일 형식, 검색어 비었거나 30자 초과, 반경 값, 대한민국 밖 좌표, 동의 안 함 | 입력칸 옆 오류 |
| 429 | 같은 이메일의 진행 중 예약 3개 / 같은 IP 하루 5건 / 오늘 발송 한도(450통) 도달 | 다시 시도 안내 |
| 502 | 확인 메일 발송 실패(예약은 저장되지 않음) | 잠시 뒤 다시 시도 안내 |
| 503 | 서버 설정 없음(Preview 환경 등 — Preview에는 메일 설정을 넣지 않는다) | 일시적으로 사용할 수 없음 안내 |

## 3. API

모든 응답은 `Cache-Control: no-store`.

### `POST /api/alerts` — 예약 만들기

```json
요청 {
  "email": "user@example.com",
  "query": "에어팟",
  "places": [
    { "name": "서울역", "latitude": 37.5547, "longitude": 126.9707 },
    { "name": "시청", "latitude": 37.5658, "longitude": 126.9772 }
  ],
  "radius_m": 1500,
  "consent": true
}
응답 202 {
  "status": "pending",
  "message": "확인 메일을 보냈습니다. 24시간 안에 링크를 눌러 주세요."
}
```

- `places`의 각 항목은 화면 `Place`의 `name`·`latitude`·`longitude` 그대로다(화면 순서대로, 1~3개). 기관 목록이 아니라 **기준 지점**이다. 서버가 비교할 때마다 장소들 각각의 반경 안 기관을 다시 계산해 합친다.
- 0개이거나 4개 이상이면 400. 좌표가 같은 장소는 서버가 하나로 합친다.
- `radius_m`: 1000 · 1500 · 2000(모든 장소에 같이 쓴다). `latitude`·`longitude`는 숫자(문자열 아님).
- 옛 형식(`place_name`·`latitude`·`longitude`를 맨 위에 두는 것)은 받지 않는다.

### `GET /api/alerts/summary?token=…` — 링크 페이지의 조건 요약 (상태를 바꾸지 않는다)

```json
응답 200 {
  "status": "pending | active | expired | cancelled | unconfirmed_expired",
  "places": [{ "name": "서울역" }, { "name": "시청" }],
  "radius_m": 1500,
  "query": "에어팟",
  "expires_at": "2026-11-14T00:00:00+09:00",
  "last_day": "2026-11-13",
  "extensions_left": 3
}
```

- 화면에는 `last_day`를 "11월 13일(금)까지"처럼 보여 주면 된다. `expires_at`은 그 다음 날 0시다.

### `POST /api/alerts/confirm` · `/extend` · `/cancel`

```json
요청 { "token": "..." }
응답 200 { "result": "...", "message": "한국어 안내" }
```

토큰이 틀릴 때만 400 "링크가 올바르지 않습니다". 화면은 `result`로 상태를 나누고 `message`를 그대로 보여 준다.

| 동작 | `result` 값 |
| --- | --- |
| 확인 | `confirmed` · `already_active` · `link_expired`(24시간 지남) · `ended` |
| 연장 | `extended`(응답에 `expires_at`·`last_day`·`extensions_left` 추가) · `limit_reached` · `ended`(만료됐거나 확인 전) |
| 취소 | `cancelled` · `already_ended` |

## 4. 메일 속 링크 페이지 — 확인·연장·취소

- 경로: `/alerts/confirm?token=…` · `/alerts/extend?token=…` · `/alerts/cancel?token=…` (메일 속 링크가 이 주소를 연다. 바꾸려면 `alerts/links.py`의 `LINK_PATHS`도 같이 바꾼다)
- 서버는 이 세 경로에서 `index.html`을 내보낸다(`Referrer-Policy: no-referrer`). React Router 경로만 추가하면 된다.
- **페이지를 열기만 해서는 처리하지 않는다.** `summary`로 조건을 보여 주고, 버튼을 눌렀을 때만 POST를 보낸다. 메일 보안 검사기가 링크를 미리 열어 보는 경우가 있기 때문이다.
- 보여 줄 결과: 확인 완료 · 이미 켜져 있음 · 링크 만료 · 연장 완료(새 마지막 날, 남은 연장 횟수) · 더 연장할 수 없음 · 취소 완료 · 이미 끝난 예약

## 5. 참고 — 메일 쪽 동작 (화면 작업 아님)

- 발신자 표시: `리트리버 <서비스 Gmail 주소>`
- 하루 450통(확인·알림·종료 안내 합계). 넘으면 예약 API가 429를 돌려준다
- 알림 메일: 예약당 하루 최대 1통, KST 11시대, 물품 최대 5개 + "그 밖에 N개", 보관기관 이름·전화번호
- 문구는 "유사한 물품이 새로 등록됐습니다"이고 본인 물건이라고 단정하지 않는다(AGENTS.md 2장 10번 부연)
- 모든 메일에 취소 링크, 알림·종료 안내 메일에 연장 링크(남은 횟수가 있을 때)
