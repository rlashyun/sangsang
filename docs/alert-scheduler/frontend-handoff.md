> 권희준 → 강지현(예약 입력 화면 담당). 2026-11-06 설계 중 정한 내용을 모은 초안이다. 백엔드 설계는 같은 폴더의 `2026-11-06-email-scheduler-design.md`에 있다.
> 백엔드 설계(테스트 계획 포함)가 확정되면 최종본으로 고쳐 GitHub에 올린다.

## 1. 예약 입력 화면

### 입력

- 이메일
- 개인정보 수집·이용 동의 체크 — 동의하지 않으면 예약할 수 없다
- 검색어는 지금 검색칸의 값을 그대로 쓴다. **1~30자 필수**다. 검색어 없이 장소만으로는 예약을 받지 않는다

### 동의 문구에 들어가야 할 내용

개인정보 보호법 제15조 제2항이 동의를 받을 때 알리라고 정한 네 가지다. 최종 문구는 따로 확인한다.

| 항목 | 내용 |
| --- | --- |
| 수집 목적 | 저장한 조건과 유사한 습득물이 새로 등록되면 이메일로 알림 |
| 수집 항목 | 이메일, 검색어, 기준 장소와 반경 |
| 보유 기간 | 예약이 끝나면(만료·취소, 또는 확인하지 않고 24시간 경과) 이메일을 즉시 삭제 |
| 거부 권리 | 동의하지 않을 수 있으며, 이 경우 알림 예약을 쓸 수 없음 |

### 알림 기준 안내

- 지도에서 특정 기관만 보고 있던 중에 예약해도, 예약은 **기준 지점 + 반경 전체**로 저장된다.
- 화면에 "반경 N km 안 모든 보관기관을 기준으로 알려 드립니다"처럼 안내한다.

### 예약 성공 후 안내

- 확인 메일을 보냈고, **24시간 안에** 메일 속 링크를 눌러야 알림이 켜진다는 안내
- **요청: 확인 메일이 스팸함으로 갈 수 있다는 안내를 넣어 주세요.** 아래는 예시 문구이고, 최종 표현은 화면에 맞게 정해 주세요.
  - "메일이 보이지 않으면 스팸함이나 프로모션함도 확인해 주세요."
  - "몇 분이 지나도 메일이 오지 않았다면 스팸함·광고함에서 '리트리버'를 찾아 주세요."
  - 이유: 팀 도메인 없이 Gmail로 보내기 때문에 스팸으로 분류될 가능성이 있다. 확인 링크를 못 누르면 예약이 켜지지 않는다.

### 오류 상태

서버가 돌려주는 한국어 메시지를 그대로 보여 주면 된다.

| 코드 | 언제 | 화면 |
| --- | --- | --- |
| 400 | 이메일 형식 오류, 검색어 비었거나 30자 초과, 반경 값 오류, 동의 안 함 | 입력칸 옆 오류 |
| 429 | 같은 이메일의 진행 중 예약이 3개 / 같은 IP 하루 5건 / 오늘 발송 한도 도달 | 다시 시도 안내 (**합의 필요** — 지금 API에 없는 코드) |
| 502 | 메일 발송 실패 (예약은 저장되지 않음) | 잠시 뒤 다시 시도 안내 |
| 503 | 서버 설정 없음 (Preview 환경 등) | 일시적으로 사용할 수 없음 안내 |

### 정해야 할 것

- 예약 입력을 검색 결과 0건일 때만 보여 줄지, 결과 아래에 늘 둘지 — ⑦에서 정한다 (`docs/team-roles.md`)
- (선택 아이디어) 검색어가 너무 넓을 때(예: "에어팟") 색상·특징을 더 적도록 안내 — 메일에 남의 물건이 많이 실리는 것을 줄인다

## 2. 메일 속 링크 페이지 — 확인·연장·취소

- 경로 제안: `/alerts/confirm?token=…` · `/alerts/extend?token=…` · `/alerts/cancel?token=…` (**합의 필요**)
- **페이지를 열기만 해서는 처리하지 않는다.** 조건 요약과 버튼을 보여 주고, 버튼을 눌렀을 때만 POST를 보낸다.
  - 이유: 메일 보안 검사기가 링크를 미리 열어 보는 경우가 있다. 열기만 해도 처리되면 사용자 모르게 예약이 켜지거나 취소된다.
- 보여 줄 결과 상태: 확인 완료 · 이미 켜져 있음 · 링크 만료(24시간 경과) · 연장 완료(남은 연장 횟수) · 더 연장할 수 없음 · 취소 완료 · 이미 끝난 예약
- 지금 서버는 `/`만 화면으로 내보낸다. `/alerts/...` 경로에서도 `index.html`을 내보내도록 서버(`web/app.py`)를 고쳐야 한다. **누가 할지 합의 필요.**

## 3. API 초안

### `POST /api/alerts` — 예약 만들기

```json
요청 {
  "email": "user@example.com",
  "query": "에어팟",
  "latitude": 37.5547,
  "longitude": 126.9707,
  "radius_m": 3000,
  "place_name": "서울역",
  "consent": true
}
응답 202 {
  "status": "pending",
  "message": "확인 메일을 보냈습니다. 24시간 안에 링크를 눌러 주세요."
}
```

- `radius_m`은 1000·3000·5000 중 하나다.
- `latitude`·`longitude`는 기관 목록이 아니라 **기준 지점 좌표**다. 서버가 비교할 때마다 반경 안 기관을 다시 계산한다.

### `GET /api/alerts/summary?token=…` — 링크 페이지의 조건 요약

```json
응답 200 {
  "status": "pending | active | expired | cancelled | unconfirmed_expired",
  "place_name": "서울역",
  "radius_m": 3000,
  "query": "에어팟",
  "expires_at": "2026-11-13T11:00:00+09:00",
  "extensions_left": 3
}
```

필드 이름은 초안이다.

### `POST /api/alerts/confirm` · `/extend` · `/cancel`

```json
요청 { "token": "..." }
```

- 응답은 200 `{ "result": "...", "message": "한국어 안내" }`이다. 토큰이 틀릴 때만 400이다. 화면은 `result`로 상태를 나누고 `message`를 그대로 보여 주면 된다(형식 합의 필요).

| 동작 | `result` 값 |
| --- | --- |
| 확인 | `confirmed` · `already_active` · `link_expired`(24시간 지남) · `ended` |
| 연장 | `extended`(응답에 `expires_at`·`extensions_left` 추가) · `limit_reached` · `ended`(만료됐거나 확인 전) |
| 취소 | `cancelled` · `already_ended` |
- 연장: 한 번에 +7일, 최대 3회(최장 4주). 만료된 뒤에는 연장할 수 없다.
- 만료 시각은 항상 **등록한 날 + 7일의 오전 11시(KST)**다. 예: 11-06 등록 → 11-13 11:00. 화면에 "11월 13일 오전 11시까지 알려 드립니다"처럼 보여 줄 수 있다.

## 4. 공개 시점

예약 화면은 **알림 판정(⑥ 검색 방식 결론 뒤 구현)이 붙은 뒤**에 사용자에게 연다. 먼저 열면 "예약은 됐는데 알림이 오지 않는" 상태가 된다.

## 5. 참고 — 메일 쪽 정해진 것 (화면 작업 아님)

- 발신자 표시: `리트리버 <서비스 Gmail 주소>` — 스팸함 안내 문구에 '리트리버'를 넣으면 찾기 쉽다. 새 Gmail 계정이라 스팸함·프로모션함으로 갈 가능성이 있어 안내 문구가 더 중요하다
- 하루에 보낼 수 있는 메일이 450통이라, 그날 한도를 넘으면 예약 API가 429("오늘 보낼 수 있는 메일을 모두 보냈습니다…")를 돌려준다
- 알림 메일: 예약당 하루 최대 1통, KST 11시대 발송, 물품 최대 5개 + "그 밖에 N개"
- 알림 문구는 "유사한 물품이 새로 등록됐습니다"이고, 본인 물건이라고 단정하지 않는다(AGENTS.md 절대 규칙 10 부연)
- 만료 전날 연장 링크가 담긴 안내 메일을 한 번 보낸다
