# 검색 지연·오탐 개선 계획 — 2026-11-11

사용자 요청: 실제 의미 검색을 유지하며 5초 이내 응답을 목표로 하고, 오탐을 줄이며 정답 보존을 평가한다. 오타 보조의 비용을 실제 비교한 후 채택 여부를 결정한다. 브랜치 `seonghyun_search`, 기준 `f8826b8`.

1. DB 실행 계획·기존 검색 실험·현재 앱을 읽고 지연 원인을 분리한다. CPU 오타 보조 on/off와 같은 질의의 결과를 비교한다.
2. 확인한 DB 병목을 최소 변경으로 개선한다. 기존 정의·권한을 보관하고 새 마이그레이션/복구 SQL을 기록한다. 정확 벡터 검색과 기관 범위를 보존한다.
3. 앱 전체 요청 예산과 후보/상세 전송을 개선한다. 의미 경로만 timeout 처리해서 전체 요청이 5초를 넘는 현재 구조를 없앤다. 불완전 응답을 정상 결과로 위장하지 않는다.
4. 오탐/미탐 평가를 기준으로 후보 판정을 조정한다. 오타 보조 제거 또는 대체는 시간·정답 비교 후 결정한다.
5. 각 단계 테스트/커밋 후 push, Preview 완료 및 실제 검색 시간/semantic_status를 검증하고 측정·복구 기록을 갱신한다.

DB→API→Preview 순서다. 외부 장애나 네트워크까지 절대 5초 성공을 보장할 수는 없으며, 테스트 범위와 timeout/실패 상태를 구분한다. 모델·원문·기존 벡터는 유지한다. 새로운 근사 인덱스 도입은 정확 검색으로 해결되지 않을 때만 검토한다.

체크포인트는 각 단계 자동 검사와 코드 검토로 진행한다. 사용자는 이미 구현과 실험을 요청했다. 미탐 0은 무한 질의 보장이 아닌 명시한 평가셋의 관측값으로만 보고한다.
